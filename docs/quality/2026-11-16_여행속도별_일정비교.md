# 여행 속도별 일정 비교 (2026-11-16)

[취향·감성 반영 계획](../ai/취향_감성_반영_계획.md) 2단계(속도 반영)가 실제 일정에서 어떻게 달라지는지 확인했다.

## 진행 방법

- 로컬 웹 서버(8080, `sqlserver-windows` 프로필, 브랜치 `feature/place-value-score` `6a52694`)에서 **비회원**으로 진행했다.
- 같은 조건을 세 번 입력하고 **여행 속도만** 바꿨다: 조건 고르기 → 강원 · 바다 · 자차 · 2일 → 여행지 추천 → **강릉** 일정 만들기 → 숙소 포함, 출발일 2026-11-26(목), 출발지 비움.
- 시간(09:00~18:00), 기본 체류시간(90분), 하루 방문 수는 화면 기본값 그대로다.
- 추천과 장소 고르기에 GPT가 들어가 실행마다 후보가 조금씩 다르다. 장소 이름보다 **하루 장소 수·체류시간·저녁 관광**을 비교한다.
- 비회원 초안은 30분 뒤 만료된다. 일정 내용은 이 문서가 기록이다. OpenAI 호출은 추천 3회와 일정 3회분이 있었다.

> 정정(같은 날): 조건 입력 화면이 이전 선택을 기억해, '보통' 실행은 바다 취향이 빠진 채 만들어졌다(작업 요청 JSON으로 확인). 속도는 맞게 들어갔다. 자세한 내용은 [여행 분위기별 일정 비교](2026-11-16_여행분위기별_일정비교.md) 마지막 절.

- **느긋하게는 의도대로 달라졌다.** 하루 3곳, 저녁 관광 없음, 같은 종류의 장소에 더 오래 머문다(경포대·오죽헌·중앙시장 60 → 80분, 아르떼뮤지엄 90 → 120분, 해변 120분). 둘째 날이 1시간 이상 일찍 끝난다.
- **알차게는 보통과 거의 같았다.** 둘 다 1일차 낮 5곳 + 저녁 1곳, 2일차 4곳이다.

## 알차게가 달라지지 않은 이유

- 보통도 이미 '짧게 들르는 곳이 많으면 한 곳 더'(10-31 규칙)로 1일차 5곳을 채웠다. 알차게는 이 상한을 5곳 → 6곳까지 열지만,
- 하루가 09:00~18:00이라 5곳과 점심을 넣으면 숙소 도착이 17:13~17:50이다. **장소 수 상한이 아니라 하루 시간이 먼저 찬다.**
- 즉 기본 시간에서는 '알차게 = 상한 한 곳 늘리기'만으로는 효과가 거의 없다. 시간을 늘리거나 한 곳에 머무는 시간을 줄여야 차이가 난다.
