## 2026-10-31 일정 수정에서 바뀐 부분 표시와 직전 일정 되돌리기 (SFR-08-04 범위 변경, 사용자 요청, DOCX 본문 미반영)

수정안 초안 화면과 저장 일정 상세에서 수정 전과 비교해 바뀐 관광지·식당·숙소·시각·설정을 보여 주고, 저장 일정에 적용한 수정은 직전 한 단계만 되돌릴 수 있게 했다(한 번 더 누르면 취소). 자세한 내용과 수용 기준은 [변경 내역](요구분석서_3.1_변경내역.md)의 2026-10-31 절에 적었다. 요구번호·개수는 그대로이고 DOCX 본문은 이번에 수정하지 않아, 아래 본문 문장과 구현이 다르다.

- SFR-08-04(일정 수정, 본문 2곳): "과거 대화 기억과 이전 버전 복원은 제외한다" → 과거 대화 기억은 제외하고, 저장 일정에 적용한 수정은 직전 한 단계만 되돌릴 수 있다. 수정 전과 비교해 바뀐 부분을 보여 준다.

## 2026-10-30 여행지 추천 근거 개선 (SFR-03·SFR-06-02 보완, 사용자 요청, DOCX 본문 미반영)

여행지 후보와 추천 이유를 관광공사에 등록된 그 지역의 장소를 근거로 고르고 쓰게 했고, 울릉도 여행의 집 출발·귀가 시간을 여객선 운항 정보로 찾게 했다. 자세한 내용과 수용 기준은 [변경 내역](요구분석서_3.1_변경내역.md)의 2026-10-30 절에 적었다. 요구번호·개수는 그대로이고 DOCX 본문은 이번에 수정하지 않아, 아래 본문 문장과 구현이 다르다.

- 3절 개발 범위·12절 제약(2026-09-23 반영): "전국 17개 시·도 28곳" → 지역을 비운 문장 입력에서 AI가 제안하고 서버가 확인한 시·군을 여행지로 추가하므로 고정 개수가 없다(2026-10-30 이 PC DB 50곳).
- SFR-03-04(여행지 후보 추천): 여행지별 "할 수 있는 것" 목록(관광공사 소분류별 등록 장소 수·이름)을 근거로, 문장 입력은 AI가 근거를 보고 5곳을 고른다.
- SFR-03-05(추천 이유 제공, 2026-09-23 반영): "전시·체험 내용은 확인하지 않았음을 함께 안내" → 이유 문장에서는 확인을 미루는 말을 빼고 결과 화면 공통 안내로 알린다.
- SFR-06-02(이동 시간, 2026-10-11 반영): "여객선 제외" → 울릉도는 TAGO 국내선박운항정보 오늘 운항편으로 찾는다. 제주 배편은 여전히 찾지 않는다.

## 2026-10-28 장소 평가 한줄평·최근 평가 보기 (SFR-10 보완, 사용자 요청, DOCX 본문 미반영)

사용자가 2026-10-28 "평가에 한줄평을 추가하고 다른 사용자의 평가를 확인할 수 있으면 좋겠다"고 해 SFR-10을 보완했다. AGENTS.md 7절의 경량 후기(별점·태그) 범위 안에서 한 줄 문장만 더하며, 후기 게시판·신고·좋아요·답글은 넣지 않는다. 요구번호·개수는 그대로이고 DOCX 본문은 이번에 수정하지 않았다. 중간발표(2026-10-29) 뒤 일정표의 '사용자 평가' 기간(11.03~11.16)에 해당하는 작업이며, 다른 회원의 평가를 추천에 반영하는 것은 이후 검토 대상이다.

- SFR-10-01·03(등록·갱신): 별점·태그에 더해 선택 입력 한줄평(최대 100자, 앞뒤 공백 제거, 비우면 저장하지 않음)을 함께 저장·갱신한다. DB는 `place_ratings.comment NVARCHAR(200) NULL`(SQL 018)이다.
- SFR-10-02(요약 조회): 평균 별점·평가 수·많이 고른 태그 아래에 그 장소의 최근 평가 최대 5건(별점·태그·한줄평·작성 시각)을 접힌 목록으로 보여 준다. 평가자는 닉네임 앞 글자만 남기고 가린다(예: 김**). 한줄평이 없는 평가도 별점·태그는 보인다. 장소 후보 화면(UI-11 장소 목록)과 저장 일정 상세(UI-14)에 표시하며 비회원도 볼 수 있다.
- SFR-10-02 보조 화면 '평가 둘러보기'(사용자 요청, 같은 날): 내 여행 메뉴에 탭을 두고, 최근에 평가가 남은 장소부터 최대 30곳의 요약과 최근 평가 5건을 장소 이름 검색과 함께 모아 보여 준다. 회원만 보며 글을 쓰거나 답글을 다는 기능은 없다(읽기 전용, 게시판 아님). DB 변경 없음.
- SFR-10-04(삭제)와 관리자 범위: 본인 삭제만 있고 관리자 한줄평 삭제·관리 화면은 만들지 않는다(AGENTS.md 6절). 부적절한 한줄평은 기존 회원 이용 제한(SFR-15)으로 대응한다.

## 2026-10-28 관리자 키워드 관리 다시 포함 (사용자 결정, DOCX 본문 수정)

사용자가 2026-10-28 관리자 키워드 관리(SFR-12·UC-12)를 다시 구현 범위에 넣기로 했다. AGENTS.md 6절은 "관리자는 회원 관리와 키워드 관리만 하고 여행지·관광지·숙소·음식점 CRUD는 하지 않는다"로 고쳤다. 2026-10-11에 붙인 제외 표시를 본문에서 지우고 실제 구현 범위를 적었다(수정일 2026.10.28). 요구번호·개수(기능 72개·전체 113개)와 표 구조는 그대로다.

- SFR-12-01: 요구사항 목록의 우선순위를 "제외"에서 원래 값 R1로 되돌렸다. 목록 설명·상세 정의·세부내용의 "[구현 범위 제외]"와 제외 사유를 지우고 구현 범위를 적었다. 카테고리는 조건 입력 화면의 질문과 연결되어 추가·삭제하지 않고 명칭·표시 순서·사용 여부만 고친다. 키워드는 조회·수정하고 삭제 대신 사용 중지하며 코드와 값은 바꾸지 않는다. 새 키워드는 동행자·여행 취향에만 추가하고, 추천 규칙이 이름을 그대로 쓰는 지역·계절·이동수단과 기본 여행 취향 6개는 이름을 바꾸지 않는다.
- UC-12: 사용 사례 관계도, 개요 표, 상세 사용사례 제목·개요의 "(구현 범위 제외)"를 지웠다. 기본 시나리오 3단계(키워드 추가 또는 카테고리·키워드 수정)와 6단계(삭제하지 않고 사용 중지), 예외 A2(사용 중 키워드 삭제 → 이름 고정 키워드 안내)를 구현에 맞게 고쳤다.
- 개발 범위 '아홉째', 사용자 유형·용어의 관리자 설명, 개발 기간표(관리자 키워드·회원 관리), 우선순위 요약의 "관리자 기능은 회원 관리로 제한하며 …·키워드 CRUD를 제공하지 않는다"를 키워드 관리를 포함하도록 고쳤다.

확인: document.xml 문장 치환 20곳(대상 문장이 XML에 정확히 한 번씩 있는지 먼저 셌다) 후 jar로 다시 압축했다. 본문을 다시 추출해 "구현 범위 제외"가 0개임을 확인했고, Word로 열어 문단 5,318개·표 162개·셀 3,396개가 원본과 같음을 확인했다. 바뀐 10·44·45·100·101쪽은 Word에서 PDF로 내보내 눈으로 확인했다.

## 2026-10-11 구현 반영 (DOCX 본문 수정)

2026-09-23 이후 변경 내역에만 적혀 있던 구현 내용을 `창프2_요구분석서 3.1_통합최종본.docx` 본문에 반영했다(수정일 2026.10.11). 요구번호·개수(기능 72개·전체 113개)와 표 구조는 바꾸지 않았고 문장만 고치거나 덧붙였다.

- 가상 예약·결제(SFR-13·16): 2026-10-09 결정대로 정식 기능으로 고쳤다. 개발 범위 '열째'·개발 기간표·용어 정리·제약사항의 "3순위 선택적 확장 기능/구현하는 경우" 문구를 "체험용 정식 기능"으로 바꾸고, 요구사항 목록의 우선순위 R3 10개(SFR-13-01~07, SFR-16-01~03)를 R2로, 사용 사례 관계도의 "(R3)" 표기를 지웠다. SFR-13-01 세부내용에 예약 대상(저장 일정의 숙소·체험용 객실 6종, 입장권 분류 관광시설, 식당 제외)을 적었다.
- 관리자 키워드 관리(SFR-12·UC-12): AGENTS.md 6절에 따라 구현 범위에서 제외했음을 표시했다. 요구사항 목록의 우선순위를 "제외"로 바꾸고 설명·정의·세부내용·사용 사례 개요에 "[구현 범위 제외]"를 붙였다. 개발 범위 '아홉째', 사용자 유형·용어의 관리자 설명에서 키워드 관리와 "가상 예약·결제 운영 정보 조회"를 뺐다(관리자 예약 조회 화면은 없다). 항목 삭제·번호 재부여는 하지 않았다.
- 회원 출발지(2026-09-29): SFR-01-01·01-04·01-05 세부내용에 '주로 출발하는 곳' 입력·수정·탈퇴 시 삭제를, SFR-04-03에 첫날 09:00 출발·마지막 날 20:00 귀가와 출발지 기본값을 적었다.
- 빈 조건 채우기·AI 제안 방향·제외 지역·축제(2026-10-03·04·05): SFR-02-02(홈 화면 지역 축제 → 조건 미리 채움), SFR-02-03(계절 채움, AI 제안 방향 3가지, 제외 지역 최대 5개), SFR-03-04(제안 방향 반영, 여행지별 축제 최대 3개, 다른 계절 여행에는 지금 축제 미표시), SFR-04-03(축제 장소는 자동 추가 대신 제안, AI 장소별 이유 한 문장).
- 예산(2026-09-21·10-10): SFR-03-03에 국민여행조사 참고값·숙소 예산대를, 5절 SFR-04-06에 항목별 예상 경비를 적었다.
- 비행기 이동시간(2026-10-03): SFR-06-02에 TAGO 국내항공운항정보 기반 집 출발·귀가 시간 계산과 한계(여객선 제외)를 적었다.
- 반려동물 동반·AI 웹 검색(2026-10-10·11): SFR-04-05에 항목별 동반 정보·관광지 사진 표시를, 5절 SFR-04-06에 '반려동물 동반'·'여행 목적 활동' 항목과 버튼(설정 시 자동) AI 웹 검색·출처 확인 구분을 적었다.
- 지도 실제 경로(2026-10-04): SFR-11-03에 자동차 초안의 도로 경로 선 표시를 적었다.

확인: DOCX 안의 document.xml을 직접 치환(51곳)해 다시 압축한 뒤 본문 텍스트를 다시 추출해 바뀐 문장과 "3순위 선택적 확장"·"(R3)" 잔존 여부를 확인했다. Word로 열어 문단 5,318개·표 162개·셀 3,396개가 원본과 같음을 확인했고 요구사항 목록 표(SFR-12·13) 화면을 눈으로 확인했다. Word COM 찾기·바꾸기는 느리고 중간에 Word가 종료돼 쓰지 않았다.

## 2026-10-09 현재 구현 기준 확정 (사용자 결정)

- 가상 예약·결제(SFR-13·16)는 정식 구현 기능으로 분류한다. 과거 우선순위 표기와 관계없이 DB 설계 대상 18개 테이블에 포함한다. 실제 시설 예약·실제 금전 결제는 범위 밖이다.
- 가상 객실 6종과 reservation_stock.room_type은 기존 예약 브랜치 a491c3e의 구현이며 이 PC DB 적용을 확인했다. 2026-10-09 main에 병합했다.
- 이 변경 내역이 과거 선택 기능 분류보다 우선한다. DOCX 본문은 이번에 수정하지 않았다.

## 2026-09-29 회원 출발지 추가 (사용자 결정, DOCX 본문 미반영)

- SFR-01(회원가입·사용자 정보 조회/수정): 회원가입과 내 정보에서 '주로 출발하는 곳'을 선택 입력으로 받고 고칠 수 있게 했다. 자유 입력(최대 60자)이며 탈퇴하면 지운다.
- 일정 입력(SFR-04-01·03, 첫날 집 출발·마지막 날 귀가): 회원이 적어 둔 출발지를 출발지 칸의 기본값으로 넣고, 화면에서 고치면 그 일정에만 쓴다. 카카오 길찾기에만 쓰며 GPT 요청·로그에는 넣지 않는다.
- 이유: 일정마다 출발지를 적거나 휴대폰 위치 권한을 허용하지 않아도 되게 한다. DB는 `users.home_area` 컬럼을 추가했다(SQL 015, DB 정의서 1.14).
- DOCX 본문과 요구사항 번호·개수는 이번에 고치지 않았다. 본문에 반영할지는 따로 정한다.

## 2026-09-23 구현 반영 (DOCX 본문 수정)
