# 요구분석서 3.1 통합 변경 내역

기준일: 2026-09-16

현재 기준 문서: `창프2_요구분석서 3.1_통합최종본.docx`

## 2026-09-23 구현 반영 (DOCX 본문 수정)

지금까지 구현한 변경 가운데 본문과 어긋난 항목만 골라 `창프2_요구분석서 3.1_통합최종본.docx` 본문을 직접 고쳤다. 요구사항 번호·개수·표 구조는 바꾸지 않았고 문장만 바꿨다(13곳).

- 3절 개발 범위와 12절 제약: R1 구현·통합 테스트를 강릉·부산·경주 3개 지역으로 제한한다는 문장을 전국 17개 시·도 28곳으로 고쳤다. 관광지 정보를 저장한 지역은 6곳이고 나머지는 지도 검색으로 후보를 확보한다는 설명을 넣었다.
- SFR-02-04(여행 조건 확인) 세부내용·검증 기준: 입력 → 보완 → 확인 순서 대신, 분석·검증 후 바로 추천하고 결과 화면에서 조건을 확인·수정한다는 흐름으로 고쳤다.
- SFR-03-02(모호한 조건 해석 및 보완) 세부내용과 5절 '모호한 입력' 판정 규칙: 추천을 막지 않는 항목은 되묻지 않고 결과 화면에서 확인하며, 일정 생성에 필요한 값만 그 단계에서 입력받는다고 고쳤다.
- SFR-03-01(여행 조건 분석): 키워드로 표현하기 어려운 구체적 여행 목적을 별도 항목으로 보존한다는 문장을 넣었다.
- SFR-03-04(여행지 후보 추천): 목적을 시설 검색어로 바꿔 관광정보·지도에서 시설을 찾고, 시설이 있는 여행지를 먼저 고르며, 못 찾으면 목적과 가까운 분류를 취향 다음으로 반영한다는 내용을 넣었다.
- SFR-03-05(추천 이유 제공): 목적 시설을 근거로 설명하되 전시·체험 내용은 확인하지 않았음을 함께 안내한다는 내용을 넣었다.
- SFR-04-01(여행 기간 확인): 기간 미정이면 일정 생성 단계에서 여행 일수(1~7일)와 숙박 여부를 입력받는다는 내용을 넣었다.
- SFR-04-03(날짜별·시간대별 일정 생성): 하루 관광지 수를 하루 가능 시간과 체류시간으로 정해 실제 이동시간으로 조정하고, 같은 종류를 연달아 두지 않으며, 못 넣은 자리는 예비 관광지로 채운다는 내용을 넣었다.
- SFR-05-02(실제 숙소 추천), SFR-17-01(실제 음식점 후보 제공): 요청 시 참고 가격을 웹 검색으로 찾아 출처·확인 수준과 함께 표시하고 장소별로 일정 기간 보관한다는 내용을 넣었다.

### 반영하지 않은 것

- 요구사항 번호 추가·삭제, 기능 72개·전체 113개 표기, 표 구조는 그대로 두었다.
- 가상 예약·결제(SFR-13·16)는 본문의 3순위 선택적 확장 설명을 유지했다. 구현은 마쳤으며 구현 상태는 `docs/progress.md`에 기록한다.
- 관리자 키워드 관리(SFR-12)는 AGENTS.md 6절에 따라 범위에서 제외하지만, 본문 요구사항 목록은 이번에 손대지 않았다.

### 확인 결과

- 편집은 `word/document.xml` 문장 치환 13곳이며 스키마 검증(`validate.py --original`)을 통과했다. 단락 수 3945개로 변화 없다.
- 이 PC에 LibreOffice가 없어 PDF 렌더링 확인은 하지 못했다. 표 잘림·줄바꿈은 Word에서 직접 확인이 필요하다.
- 코드·DB 변경이 없어 Maven 테스트는 실행하지 않았다.

## 2026-09-22 사용자 요청에 따른 조건 확인 흐름 조정

- SFR-02-04·SFR-03-02: 자연어 입력 후 분석·검증을 거쳐 바로 추천한다. 조건 확인·보완을 매 요청의 필수 독립 단계로 강제하지 않고, 추천 화면에서 해석한 조건을 확인하고 필요할 때 수정한다. 서버 검증과 오류 안내는 유지한다.
- SFR-04-01: 지역 추천에 기간을 요구하지 않는다. 일정 생성 시 미정 여행 일수와 여러 날 여행의 숙소 필요 여부를 받는다. 이미 명시된 조건은 임의 변경하지 않는다.
- 여행 활동 목적은 별도 필드로 보존하며 후보 근거가 없으면 미확인으로 설명한다. 실제 관련 시설 검색·전시 정보 확인은 별도 후속 보완이다.
- 이 조정은 본 변경 내역과 화면 추적표에 반영했고, 2026-09-23에 DOCX 본문에도 반영했다(위 '2026-09-23 구현 반영' 참고).

- SFR-02-06 탐색 취향 확인과 추천 반영을 추가했다.
- SFR-02-07 필수 조건과 선호 조건 구분을 추가했다.

- SFR-04-03에 방문 시작·종료 시각, 활동 내용, 체류시간과 여행 시작·종료 가능 시간 입력 기준을 반영했다.

## 범위 결정

- 관리자 기능은 `AGENTS.md`에 따라 회원 관리로 제한한다.
- 관리자 여행지·관광지·숙소·음식점·키워드 CRUD는 추가하지 않는다.
- 취향 탐색과 부분 재추천은 초기 지원 지역인 강릉·부산·경주 범위를 임의로 확대하지 않는다.
- 동행자별 취향 조율, 빈 시간 여행, 날씨 자동 변경, 전국 데이터 확대는 이번 통합 범위가 아니다.
- 이번 문서 통합으로 DB 테이블이나 컬럼을 확정하거나 변경하지 않았다. 저장 구조는 구현 전에 DB 정의서와 ERD를 대조한다.
- 추가 요구사항은 구현 예정 범위이며 기능 구현 완료를 의미하지 않는다.

## 확인 결과

- DOCX 압축 구조와 본문·표 추출을 확인했다.
- 표 162개와 기존 요구사항 상세표가 유지되는지 확인했다.
- SFR-02-05~07, SFR-04-06~07과 기능 72개·전체 113개 표기가 포함되는지 확인했다.
- 접근성 검사에서 high·medium·low 항목이 모두 0건이었다.
- 번들 문서 렌더러에는 LibreOffice가 없어 `render_docx.py`는 실행하지 못했다. 대신 Microsoft Word 2024로 읽기 전용 PDF를 출력하고 105페이지 전체 이미지를 확인했다.
- 표·본문 잘림, 겹침, 비정상 빈 페이지를 발견하지 않았다. 최초 확인에서 총괄표의 TOTAL이 108로 남은 문제를 발견해 113으로 수정한 뒤 해당 페이지를 다시 렌더링했다.
- 코드·DB 변경이 없어 Maven 테스트와 DB 테스트는 실행하지 않았다.
