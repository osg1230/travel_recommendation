# 요구분석서 3.1 변경 내역

기준일: 2026-09-15

현재 기준: [요구분석서 3.1](창프2_요구분석서%203.1_취향탐색_일정상세화.docx). 3.0 원본은 보존한다. 새 기능은 구현 예정이며 DB 변경은 없다.

## SFR-02-05 선택형 여행 취향 탐색

R1 / UI-08, UI-09

비회원과 회원은 기존 자연어·키워드 입력 또는 선택형 취향 탐색을 선택한다. 탐색은 여행 장면을 비교하는 3~5개 질문으로 구성한다. 예를 들어 바다 앞 카페에서 쉬기와 시장·골목 둘러보기 중 더 끌리는 장면을 고른다. 각 질문에는 상관없음과 건너뛰기를 제공하고 이전 선택을 수정할 수 있다.

수용 기준: 모두 건너뛴 경우 선호를 임의 생성하지 않고 기존 조건 입력으로 진행한다. 위조된 질문·선택지 ID는 서버에서 거부한다.

## SFR-02-06 탐색 취향 확인과 추천 반영

R1 / UI-09, UI-10, UI-12

선택지에 연결한 태그와 단순 점수 규칙으로 이번 여행의 선호를 도출한다. AI는 결과 설명과 추천을 보조하며 선택 사실을 임의 생성하지 않는다. 사용자는 도출된 취향과 선택 근거를 확인·수정한 뒤 확정한다. 명시적으로 입력한 조건과 충돌하면 사용자에게 확인한다. 미선택은 비선호로 해석하지 않으며 영구적인 성격으로 단정하지 않는다. 추천 결과에는 반영된 취향과 해당 장소·일정의 연결을 설명한다.

수용 기준: 동일 선택에는 동일한 규칙 결과가 나오며, 선택 수정 시 이전 점수를 누적하지 않고 다시 계산한다. 확정한 취향이 추천 요청에 전달되고 실제 반영 여부를 설명하는지 확인한다.

## SFR-02-07 필수 조건과 선호 조건 구분

R1 / UI-09

사용자는 지원하는 조건을 반드시 지킬 조건과 가능한 경우 반영할 선호 조건으로 구분한다. 여행 기간, 하루 방문 장소 수, 필수 방문 장소 등 검사 가능한 조건부터 지원한다. 예산은 인당·전체와 포함 비용 범위를 확인한다. 조건이 충돌하면 임의 완화하지 않고 충돌 이유와 변경 선택지를 제시한다.

수용 기준: 모순된 필수 조건을 그대로 확정하지 않는다. 가격 자료가 부족하면 예산 충족을 확정하지 않고 확인 필요로 표시한다.

## SFR-04-06 여행 조건 충족 결과 표시

R1 / UI-12, UI-14

서버가 확정 조건과 생성 결과를 비교해 충족·미충족·확인 필요를 표시한다. 기간, 하루 방문 수, 필수 장소 포함, 중복, 시간 충돌을 검사한다. 고른 여행 취향에 맞는 관광지가 들어갔는지는 선호 조건이라 충족 또는 확인 필요로만 표시한다(2026-09-23, 장소 분류·이름 기준). 예산은 확인 가능한 비용과 예상 범위·누락 항목을 표시한다. 영업시간·가격·이동시간의 출처와 확인 범위가 부족하면 검증 완료로 표시하지 않는다. 필수 조건 미충족 또는 시간 충돌이 남으면 완료 일정으로 확정하지 않고 수정 안내를 제공한다.

수용 기준: AI가 충족이라고 설명하더라도 서버 계산이 우선한다. 정보 부족과 실제 위반을 구분하고 임의의 적합도 점수를 사용하지 않는다.

## SFR-04-07 장소 고정과 부분 재추천

R2 / UI-12, UI-14, UI-15

사용자는 유지할 장소와 교체할 장소를 선택하고 취향 불일치·비용 절감·실내 변경 등의 교체 이유를 전달한다. 서버는 확인된 후보에서 교체하고 고정 장소의 식별자를 유지한다. 고정은 장소 유지이며 시각 고정을 뜻하지 않는다. 필요한 인접 시간 변경을 표시하고 전체 조건을 재검증한 뒤 사용자가 적용한다. 비회원은 유효한 임시 결과만, 회원은 본인 결과·저장 일정만 변경한다.

수용 기준: 실패·후보 없음·적용 취소 시 원본을 유지한다. 고정 장소를 누락·교체한 AI 응답은 거부한다. 부분 변경으로 생긴 시간 충돌과 권한 위반을 검사한다.

## 기존 요구사항 보완

SFR-04-03: 일차별로 방문 시작·종료 시각, 활동 내용과 예상 체류시간을 포함한 일정을 생성한다. 여행 시작·종료 가능 시간을 입력받고 미입력 시 적용할 기본 시간을 확정 전에 안내한다.
SFR-04-04: 체류·이동·식사·휴식 시간을 합산해 하루 가능 시간 안에 배치한다. 시간 중복, 음수·0 이하 체류시간, 날짜 범위 초과와 이동시간 부족을 서버에서 검사한다. 이동시간의 추정 여부·출처·확인 기준을 표시하고 영업시간 정보가 없으면 확인 필요로 안내한다.

기능 67→72개, 전체 108→113개. UC-06·07 및 기존 TER 항목 확장. 동행자 조율·전국 지원은 추가하지 않는다. DB 상세 설계와 기존 관리자 범위 불일치는 후속 검토 사항이다.

## 2026-10-03 SFR-06 교통 보완: 비행기 이동시간 (범위 확장)

제주처럼 바다를 건너는 여행은 집 출발·귀가 편도 시간을 공공데이터포털 국토교통부 TAGO 국내항공운항정보로 찾는다. 집에서 가까운 공항과 여행지에서 가까운 공항 사이의 오늘 운항편 중 가장 짧은 비행시간에 공항까지·공항에서의 이동시간(카카오 길찾기)과 공항 대기(출발 60분·도착 20분)를 더하며, 근거를 일정에 적는다. 일정 초안 화면의 "비행기로 가는 방법"은 출발 공항을 고르면 항공사별 편수·첫 편·막 편·비행시간·일반석 최저 요금을 참고로 보여 준다(여행 날짜 운항편이 없으면 오늘 기준임을 표시).

수용 기준: 운항편이나 공항까지의 길을 찾지 못하면 추정하지 않고 출발지를 비우도록 안내한다. 예약 가능 여부·실제 요금은 안내하지 않는다. 여객선(배)은 범위에 넣지 않는다. 2026-10-11 요구분석서 DOCX 본문에 반영했다.

## 2026-10-03 SFR-02·SFR-03·SFR-04 보완: 빈 조건 채우기와 여행 시기 축제 자동 반영 (범위 확장)

UI-08, UI-10, UI-12 / 사용자 피드백("아무 데나라고 하면 계절에 맞는 여행과 축제를 알아서 추천해 주면 좋겠다")에 따른 보완이다. 사용자가 말한 조건은 그대로 두고 말하지 않은 부분만 채우며, 여행지를 사용자가 고르는 단계는 유지한다.

SFR-02(조건 입력): 자연어 입력에서 계절을 말하지 않으면 서버가 여행 시작일(없으면 오늘)의 계절을 채운다. 하고 싶은 것을 말하지 않으면 AI가 계절과 입력한 지역·동행·취향에 맞는 여행 방향을 서로 다른 종류로 3가지 제안하고, 화면에 "AI가 제안한 여행 방향"으로 사용자 목적과 구분해 보여 준다. 계절·동행·취향·이동수단 선택지로 표현하지 못한 조건(야경, 반려견과 함께 등)은 버리지 않고 여행 목적에 남긴다.

SFR-03(여행지 추천): 제안 방향도 여행 목적과 같은 방식으로 관광공사·카카오에서 관련 시설을 찾아 후보 선정과 추천 이유에 반영한다. 제안 방향이 여러 개면 방향별로 맞는 여행지를 먼저 고르고, 여행지마다 방향 하나를 정해 "이런 여행으로 추천"으로 표시한다. 후보 여행지에서 여행 시기에 열리는 축제(관광공사 조회, 여행 날짜가 있으면 그 기간과 겹치는 축제, 없으면 진행 중이거나 60일 안에 시작하는 축제, 여행지당 최대 3개)를 추천 이유와 여행지 카드에 보여 준다.

SFR-04(일정 초안): 여행 기간과 겹치는 축제가 있고 축제 장소를 카카오 장소로 확인한 경우(행사 장소 이름 일치, 없으면 행사 좌표 500m 안의 가장 가까운 관광명소) 그 장소를 필수 방문 장소이자 축제를 볼 수 있는 날의 중심 장소로 넣고, 방문 이유에 축제 이름·기간을 안내한다. 출발일이 미정이면 여행 정보 화면이 축제 기간에 맞춘 출발일을 미리 넣어 제안하며 사용자가 바꿀 수 있다.

수용 기준: 사용자가 직접 말한 목적·계절·날짜는 AI 제안이나 축제 날짜로 덮어쓰지 않는다. AI 제안은 사용자 목적과 구분해 표시한다. 축제 이름·기간은 관광공사 조회 값만 표시하고 AI가 만든 값을 쓰지 않는다. 축제 장소를 확인하지 못하면 일정에 넣지 않으며, 근처 명소로 넣은 경우 정확한 행사 장소 확인이 필요하다고 안내한다. 축제 조회나 장소 확인이 실패해도 추천과 일정 생성은 계속한다.

제외·한계: 추천 여행지는 등록된 여행지 범위 안에서만 고른다. 조건 선택(키워드) 입력에는 AI 제안 방향이 없다. 추천 이유 문장 속 축제 언급과 방향별 여행지 수 배분은 AI 지침으로만 요청한다. DB 테이블·컬럼 변경은 없다. 2026-10-11 요구분석서 DOCX 본문에 반영했다.

## 2026-10-10 SFR-04 보완: 반려동물 동반 여행의 장소별 동반 정보

SFR-04: 여행 목적이나 입력 문장에 반려동물(강아지·반려견·반려동물 등)이 있으면 일정 초안에 들어간 관광·식사·숙소 장소마다 한국관광공사 TourAPI의 반려동물 동반 정보(동반 가능 구분·가능한 동물·필요 사항·기타)를 조회해 일정 항목에 표시하고, AI 준비 안내와 장소별 이유에 근거로 넘긴다. 조건 확인표에 '반려동물 동반' 항목을 추가한다: 일정의 모든 장소에 동반 정보가 있고 동반 불가가 없으면 충족, 정보가 없거나 동반 불가로 안내된 곳이 있으면 확인 필요(미충족으로 저장을 막지 않는다). 반려동물 동반 여행이 아니면 해당 없음이다.

수용 기준: 동반 가능 여부는 관광공사 자료가 있는 장소만 표시하고, 자료가 없는 장소는 '정보 없음'으로 두어 방문 전 확인을 안내한다. AI는 서버가 넘긴 동반 정보만 근거로 쓰고 없는 조건을 지어내지 않는다. 조회는 일정 작업 안에서 유형과 이름이 같고 도로명 주소가 같거나 좌표가 가까운(1.5km) 곳이 하나일 때만 연결하며, 결과는 장소 상세정보에 보관해 7일 동안 재사용한다.

제외·한계: 관광공사에 등록되지 않은 장소(카카오로만 찾은 음식점·카페 등)는 정보가 없다. 동반 정보에 따라 장소를 자동으로 바꾸거나 거르지는 않는다.

## 2026-10-11 SFR-04 보완: 확인 필요 항목 AI 웹 검색

SFR-04: 일정 초안에서 서버가 확인하지 못해 "방문 전 확인 필요"로 둔 항목(관광공사 동반 정보가 없는 장소의 반려동물 동반 가능 여부, 사용자가 직접 말한 여행 목적 활동을 그 장소에서 할 수 있는지)을 AI 웹 검색으로 찾아 가능·불가·못 찾음과 근거·출처를 일정 항목과 조건 확인표('반려동물 동반', 새 항목 '여행 목적 활동')에 보여 준다. 기본은 초안 화면의 버튼으로 실행하고(유료), 설정(`travel.verification.auto`)으로 초안 생성 시 자동 실행해 AI 준비 안내에도 반영할 수 있다.

수용 기준: AI 답은 출처가 실제 검색 결과에 있을 때만 받고, 서버가 출처 페이지에서 장소 이름을 확인한 답과 확인하지 못한 답을 구분해 표시한다. 검색 결과는 확정 사실로 표시하지 않으며 조건 확인표에서 충족으로 올리지 않는다. 한 초안에서 묻는 질문은 10개 이하이고, 같은 장소·질문의 답은 7일(못 찾음 24시간) 재사용한다.

제외·한계: 운영시간 세부 조건, 혼잡도(조용한 곳), 예약 가능 여부는 검색 대상이 아니다. 서비스가 제안한 여행 방향은 묻지 않는다. 버튼으로 찾은 결과는 이미 만들어진 AI 준비 안내 문장에는 들어가지 않는다.

## 2026-10-04 SFR-02·SFR-03·SFR-04 보완: 제외 지역, 다른 계절 여행의 축제, 장소별 추천 이유

SFR-02·SFR-03: 자연어 입력에서 "부산 말고"처럼 가지 않겠다고 말한 지역(최대 5개)을 조건으로 보존하고 추천 후보에서 뺀다. 조건 요약에 제외 지역을 표시한다. 날짜 없이 지금과 다른 계절의 여행을 말한 경우 현재 열리는 축제를 그 여행의 축제로 보여 주지 않는다.
