# 가상 예약·결제 (SFR-13·16)

2026-09-22 구현. 예약·결제 과정을 체험하는 기능이며 실제 시설에 예약이 전달되지 않고 실제 돈이 오가지 않는다. 카드번호 등 금융정보를 받지 않는다.

> 2026-10-09 기준: 가상 예약·결제는 정식 구현 기능이다. 객실 6종 기능(a491c3e)은 2026-10-09 main에 병합했다. 이 PC DB에는 SQL 016의 room_type과 객실 유형별 UNIQUE 키가 적용되어 있다. 아래는 main 기준 기능 설명이다.

## 준비

- [013 SQL](../database/sql/013_create_virtual_reservations.sql)을 적용한다. 테이블 4개와 2026-10-01~2026-12-31 가상 수량 460행을 만든다.
- 수량이 있는 장소: 씨마크 호텔·신라스테이 해운대·라한셀렉트 경주(객실 5실/일), 오죽헌·시립박물관(200명/일)·동궁과 월지(300명/일).
- [016 SQL](../database/sql/016_add_reservation_room_type.sql)을 적용한다(2026-10-05). 수량 테이블에 객실 종류 컬럼을 더한다. 적용하지 않으면 예약 화면이 열리지 않는다.

## 숙소 객실 종류 (2026-10-05)

- 숙소는 모두 예약할 수 있다. 저장 일정의 숙박 항목(퇴실하는 마지막 날 제외)마다 일정표 옆에 **예약하기** 버튼이 나온다.
- 실제 호텔 객실을 가져오지 않고 흔한 객실 이름만 쓴다(`RoomType`). 가격은 기준가 × 배수를 천 원 단위로 반올림한다.

| 객실 | 최대 인원 | 배수 |
| --- | --- | --- |
| 싱글룸 | 1명 | 0.8 |
| 스탠다드 더블 | 2명 | 1.0 |
| 스탠다드 트윈 | 2명 | 1.0 |
| 디럭스 더블 | 2명 | 1.3 |
| 패밀리룸 | 4명 | 1.6 |
| 스위트룸 | 2명 | 2.0 |

- 기준가: 그 숙소에 이미 있는 스탠다드 더블 가격(시드 3곳은 기존 참고가) → 일정을 저장할 때 찾아 둔 숙소 참고 가격(최저가) → 없으면 100,000원.
- 객실 수량 행은 회원이 저장 일정 상세나 예약 신청·날짜 변경 화면을 열 때 그 숙소·날짜 분만 만든다(`VirtualReservationService.ensureRooms`). 객실 종류마다 하루 3실, 15:00 입실~다음 날 11:00 퇴실, 내일부터 1년 안의 날짜만.
- 예약 신청 화면에서 객실 종류를 고른다. 날짜 변경은 같은 객실 종류로만 되고, 종류를 바꾸려면 취소 후 새로 예약한다.

## 관광시설 예약 대상 (2026-10-05)

- 식당은 예약 대상이 아니다. 관광지는 보통 입장권을 끊고 들어가는 분류만 대상이다. 장소의 세부 분류(카카오 `subtype`)에 아래 말이 들어 있으면 대상으로 본다(`ReservationCatalog.ticketPrice`).

| 분류에 들어 있는 말 | 체험용 1인 가격 |
| --- | --- |
| 아쿠아리움, 동물원 | 25,000원 |
| 테마파크(워터테마파크 포함) | 30,000원 |
| 케이블카 | 15,000원 |
| 수목원, 식물원, 체험학습장, 관광농원 | 10,000원 |
| 박물관, 전시관, 고궁 | 5,000원 |

- 대상이 아닌 곳: 해변, 자연휴양림, 사찰·성당, 둘레길, 전망대, 거리, 섬, 산·계곡, 온천, 문화유적·릉(유료·무료가 섞여 있어 제외). 시드로 수량을 넣은 오죽헌·동궁과 월지는 그대로 대상이다.
- 수량 행은 숙소와 같이 저장 일정 상세나 날짜 변경 화면을 열 때 그 장소·날짜 분만 만든다(`ensureTickets`). 하루 100명, 09:00~18:00, 내일부터 1년 안의 날짜만. 그 장소에 이미 수량이 있으면 그 가격을 이어 쓴다(오죽헌 3,000원).
- 가격은 실제 입장료를 조회한 값이 아니며 화면에 '체험용 가격이에요. 실제 입장료와 달라요'라고 밝힌다.

## 사용자 흐름

화면에서는 2026-10-05부터 '가상 예약·가상 결제' 대신 **예약·결제**로 부른다(메뉴 '예약', 버튼 '예약하기'·'예약 신청'·'결제'). 기능은 그대로 체험용이며 각 화면의 '실제 시설에 전달되지 않고 실제 돈이 오가지 않아요' 안내는 남겼다. 클래스·테이블·URL 이름은 바꾸지 않았다.

1. 저장한 일정 상세의 **예약 (체험)** 영역: 같은 날짜에 수량이 있는 숙박·관광 항목만 보여 준다.
2. `/my/reservations/new`: 이용 일시·남은 수량·단위 가격과 가격 출처를 보고 객실 수·인원을 정한다. 다른 날짜로 바꿔 볼 수 있다.
3. 신청하면 수량을 먼저 잡고 '결제 대기'(PENDING)가 된다.
4. 예약 상세 `/my/reservations/{id}`에서 테스트 결제(성공·실패 선택), 결제 전 날짜·인원 변경, 취소(결제했으면 환불)를 한다.
5. 마이페이지 탭 **예약**에서 내역을 본다.

## 규칙 (DB 정의서 '가상 예약·결제 트랜잭션과 상태 전이')

- 수량 차감은 `remaining_quantity >= 요청 수량` 조건부 UPDATE이며 영향 행이 없으면 매진·수량 부족(409)이다.
- 예약 요청 키(request_key)와 결제 멱등키(idempotency_key)는 화면을 열 때 서버가 만들어 폼에 넣는다. 같은 폼을 다시 보내면 처음 결과를 돌려준다. 같은 결제 키로 다른 예약·금액을 보내면 거절한다.
- 결제는 예약 행을 잠근 뒤 처리해 다른 키로 동시에 결제해도 성공은 한 건이다(필터 UNIQUE 인덱스로도 보장).
- 예약: PENDING → CONFIRMED/CANCELED, CONFIRMED → CANCELED. 결제: READY → SUCCESS/FAILED, SUCCESS → REFUNDED.
- 변경은 결제 전(PENDING)만 가능하다. 결제한 예약은 취소·환불 후 새로 예약한다.
- 취소는 한 번만 수량을 복구한다. 이미 취소된 예약의 재취소·재환불은 아무것도 바꾸지 않는다.
- 객실은 1~5실, 객실당 최대 인원(객실 종류별 1·2·4명) 이내. 관광시설은 인원 1~20명만큼 수량을 잡는다.

## 한계

- 객실 종류와 가격은 체험용이다. 실제 숙소에 그 객실이 있는지, 실제 요금이 얼마인지와 관계없다. 시드 3곳의 기준가만 한 날짜(2026-11-18) 판매가를 참고했다.
- 관광시설은 분류 이름만 보고 대상을 정한다. 실제로는 무료인 박물관에도 예약 버튼이 붙고, 유료인 문화유적에는 붙지 않는다. 카카오 분류가 없는 시스템 관광지는 오죽헌·동궁과 월지만 대상이다(동궁과 월지는 2026-10-01~12-31만).
- 일정을 열어 보기만 해도 그 숙소·날짜의 객실 수량 행(6행)과 대상 관광시설의 수량 행(1행)이 만들어져 남는다. 지난 날짜의 행을 정리하는 기능은 없다.
- 결제 대기 예약의 자동 만료는 없다. 회원이 취소하거나 탈퇴할 때 수량이 복구된다.
- 관리자용 예약·결제 조회 화면은 없다.
