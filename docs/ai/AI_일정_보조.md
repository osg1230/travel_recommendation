# AI 일정 보조 안내

## 사용 흐름

장소 목록 → 하루 시간을 정하고 일정 초안 만들기 → 작업 상태 → **일정 초안과 AI 준비 안내 확인**.

별도 화면이나 버튼을 추가하지 않았다. 기존 일정 작업(`ai_jobs.job_type=ITINERARY`)의 생성 단계에서 이어서 처리한다. SQL Server 프로필과 001~007 SQL, `KAKAO_REST_API_KEY`, `OPEN_AI_API`가 필요하다. 추가 SQL·테이블 변경은 없다. 새 작업 상태도 추가하지 않았다.

`OPEN_AI_API`가 없으면 GPT를 호출하지 않고 기존과 동일한 일정 초안만 표시한다. 일정 한 건당 GPT 사용량이 최대 4회 발생한다(관광지 순서 1회 + 보조 안내 최대 3회).

## 관광지 순서 정하기 (2026-10-05)

일정 작업이 시작되기 전에(`PlacePickService`, 주변 음식점 찾기보다 먼저) 관광지 후보 전체(1~3일 16곳, 최대 27곳)의 이름·분류·일정 중심에서의 직선거리와 여행 조건(계절·동행·취향·여행 목적·이동수단)을 GPT에 보내 **갈 만한 순서(order)**와 **뺄 곳(skip)**을 받는다. 서버 규칙(중심 장소와의 거리, 분류 글자, 종류 돌려 뽑기)만으로는 덜 알려진 곳이 종류가 드물다는 이유로 먼저 뽑혔기 때문이다.

- GPT는 후보 안에서 순서만 정한다. 후보에 없는 ID·중복은 버리고, 갈 만한 곳이 비었거나 후보의 절반 넘게 빼라고 하면 응답을 쓰지 않는다. 사용자가 정한 필수·중심 장소는 뺄 곳에서 제외한다.
- 순서는 중심 장소 → GPT 순서 → GPT가 언급하지 않은 곳 → 뺄 곳이다. 종류를 돌아가며 섞지 않고, 같은 종류가 두 번 이어진 뒤에만 다른 종류를 먼저 둔다(`TripConstraints.byPicks`).
- 몇 곳을 넣을지(하루 수용량·하루 방문 수), 필수 장소, 날짜 배정, 시각·이동시간 계산과 검증은 그대로 서버가 한다. 뺄 곳은 예비·저녁 관광으로 쓰지 않고 낮 관광지가 모자랄 때만 쓰인다. 저녁 관광 후보는 낮 관광지 수만큼 건너뛴 뒤쪽에서 고른다.
- 응답 제한 20초, 재시도 없음. 실패·시간 초과·키 없음이면 작업을 만들 때 서버 규칙으로 고른 관광지를 그대로 쓴다. 수정안에서는 호출하지 않는다.
- 주소·좌표·원문·계정 정보는 보내지 않는다. DB 변경은 없고 작업 요청 JSON에 `picking`(고르기 전 후보, AI 순서 여부)만 더했다.
- GPT가 '널리 알려진 곳'이라고 판단한 근거는 모델의 지식이며 방문객 수 같은 자료로 확인한 것이 아니다.
- 2026-10-31 밤 명소(`night`): 같은 응답에 order에 적은 곳 중 낮보다 밤에 가 볼 만하다고 널리 알려진 곳(야경·야간 조명·야시장)을 최대 3곳 받는다. 서버는 그중 저녁 관광 분류(`TripConstraints.eveningSpot`, 해변·전망대·호수·거리 등)이고 필수·중심 장소가 아닌 곳만, 숙박하는 밤 수만큼 낮 관광지에서 빼고 저녁 관광 후보 맨 앞에 둔다(`PlacePickService.picked`). 일정 생성은 저녁 관광에서 이곳을 먼저 보고(식당에서 45분 안일 때), 이유에 "AI가 밤에 둘러보기 좋은 곳으로 꼽아"라고 적는다. 원래 AI 순서에서는 앞쪽을 낮 관광지로 쓰고 저녁 관광 후보를 뒤쪽에서 골라, 광안리처럼 밤에 더 좋은 곳이 낮에 먼저 들어갔다. 야간 개방·조명은 확인한 것이 아니다. 숙소에서 멀어 저녁에 갈 수 없으면 그 여행에서는 빠질 수 있다.
- 하루 시간이 남아 더 넣는 예비 관광지는 직전 방문지에서 직선 10km 안의 곳만 넣는다(`ItineraryGenerator.SPARE_MAX_KM`). 예비 관광지가 GPT 순서의 다음 곳들이라 먼 곳일 수 있어, 시간이 남았다는 이유만으로 멀리 다녀오지 않게 한다. 가까운 곳이 없으면 그 시간은 비운다.

## 보조 범위

- AI는 **이미 만들어진 초안을 읽고 준비 안내만** 작성한다. 전체 안내 1개와 일차별 안내 1개씩을 받는다.
- 시각·장소·순서·이동시간은 서버가 만든 값을 그대로 유지한다. AI 응답으로 일정을 바꾸지 않는다.
- 안내는 준비물, 이동 여유, 시간대 주의, 대안 활동처럼 사용자가 미리 준비할 내용을 다룬다.
- 영업시간·휴무·가격·예약 가능 여부·혼잡도·날씨를 확인한 결과가 아니다. 화면에도 같은 문구로 표시한다.
- 자연어 원문, 해석 요약, 계정 식별자, 세션 토큰, DB 키워드 ID는 GPT 요청에 넣지 않는다. 지역·기간·인원·숙박 여부·이동수단·계절/동행/테마 키워드 이름과 일정의 장소 이름·시각만 보낸다.

## 관광지별 추천 활동 (2026-10-31)

같은 응답의 `places`에 관광지(저녁 관광 포함)마다 그곳에서 해 볼 만한 활동 한 문장(`activity`, 90자 안팎)을 받아 일정 항목에 'AI 추천 활동' 줄로 붙인다(`PlaceReasons`). 전에는 '가 볼 만한 이유'를 'AI 설명'으로 붙였는데, 서버의 '고른 이유'와 내용이 겹친다는 사용자 의견으로 바꿨다. 고른 이유는 같은 날 짧은 꼬리표로 줄였다.

- 근거: 서버가 일정의 관광지마다 한국관광공사 소개문(`detailCommon2` overview, 600자까지)을 찾아 항목의 `overview`로 보낸다(`PlaceOverviewService`, TourAPI_설정.md). AI는 소개문에 나온 건물·볼거리·길·체험만 써서 1~2가지를 구체적으로 적고, 소개문이 없으면 이름·종류로 알 수 있는 일반적인 활동만 쓴다. 소개문에 없는 시설·체험 프로그램·메뉴·가격·운영시간·소요 시간은 지어내지 않게 지시한다.
- 식당은 받지 않는다. 메뉴를 확인하지 않아 쓸 수 있는 말이 음식 종류뿐이고, 서버의 음식 분류·꼬리표로 충분하다. 응답 형식(JSON 스키마)의 placeId도 관광지 ID만 허용한다.
- 응답 형식에서 `places`를 관광지 수만큼(minItems=maxItems) 받는다. 처음 확인에서 AI가 소개문이 있는 4곳에만 쓰고 소개문이 없는 3곳을 비웠기 때문이다.
- 형식 검사: 1~200자, HTML·링크·연락처·줄바꿈이 없고 '요'로 끝나는 문장만 받는다. 맞지 않는 문장은 그 장소만 버리고 활동 줄 없이 둔다.
- 화면 끝에 "'AI 추천 활동'은 관광공사 소개문이 있으면 그 내용을 바탕으로 AI가 쓴 할 거리로, 운영 여부·시간·가격을 확인한 내용이 아니에요"라고 알린다. 이전에 만든 초안·저장 일정의 'AI 설명' 줄은 그대로 보인다.
- 소개문 조회에 실패하거나 시간이 모자라면 소개문 없이 요청한다. 일정 생성은 실패하지 않는다.

## 검증과 자기수정

- `json_schema` strict로 응답 형식을 고정하고, 서버가 다시 검사한다. 일차 수와 일차 번호가 초안과 같아야 하며 같은 번호를 두 번 쓸 수 없다.
- 문구는 1~600자의 일반 텍스트만 받는다. HTML 표시(`<`, `>`), 링크(`http`), 연락처(`@`)가 있으면 거부한다.
- 형식이 맞지 않으면 **고정된 한국어 사유**를 전달해 다시 요청한다. 자기수정은 요구분석서 3.1의 제한에 맞춰 최대 2회이며, AI 응답 원문을 다시 보내지 않는다.
- 설정 없음·인증·사용량 제한·연결 실패·시간 초과는 다시 요청하지 않는다. 같은 결과가 나오고 유료 호출만 늘기 때문이다.
- 보조가 실패해도 일정 생성은 실패시키지 않는다. 안내 없이 초안만 제공한다. 전체 보조 예산은 45초이며 남은 시간이 없으면 재요청하지 않는다.
- 저장 직전 검증(`ItineraryGenerator.validate`)에서도 일차 수·번호와 문구 형식을 다시 확인한다. 서버 검사가 AI 문장보다 우선한다.

## 현재 한계와 다음 단계

일정의 조건 충족 여부를 판정하거나 장소를 교체하지 않는다. 요구분석서 3.1의 SFR-04-06 조건 충족 결과 표시와 SFR-04-07 장소 고정·부분 재추천은 이번 범위가 아니다. `시간대별_일정_초안.md`의 "AI 세부 일정 생성·자기수정" 중 **자기수정 제한과 보조 안내**만 연결했고, AI가 일정을 직접 생성하거나 재배치하는 기능은 없다.

안내 문구의 사실 여부는 검증하지 않는다. 형식과 일차 번호만 검사하므로 내용은 참고용이다.

## 확인 결과

- 2026-09-20 SQL Server 프로필 `clean verify` 159개 중 153개 통과, 실제 외부 API 6개는 건너뜀. Jar 빌드까지 성공했다.
- 자동 테스트에서 개인 입력 미전송, 일차 번호 불일치·중복 거부, HTML·링크·연락처·빈 문구·길이 초과 거부, 형식 실패 2회 재요청 후 성공, 3회 실패 시 초안 유지, 인증·한도·예상 밖 오류의 즉시 중단, 이전 작업 JSON 호환을 확인했다.
- 실제 GPT 응답으로 안내 품질을 확인한 기록은 아직 없다. 실물 브라우저 전체 흐름도 미검증이다.
