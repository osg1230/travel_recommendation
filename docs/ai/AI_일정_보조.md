# AI 일정 보조 안내

## 사용 흐름

장소 목록 → 하루 시간을 정하고 일정 초안 만들기 → 작업 상태 → **일정 초안과 AI 준비 안내 확인**.

별도 화면이나 버튼을 추가하지 않았다. 기존 일정 작업(`ai_jobs.job_type=ITINERARY`)의 생성 단계에서 이어서 처리한다. SQL Server 프로필과 001~007 SQL, `KAKAO_REST_API_KEY`, `OPENAI_API_KEY`가 필요하다. 추가 SQL·테이블 변경은 없다. 새 작업 상태도 추가하지 않았다.

`OPENAI_API_KEY`가 없으면 GPT를 호출하지 않고 기존과 동일한 일정 초안만 표시한다. 일정 한 건당 GPT 사용량이 최대 3회 발생한다.

## 보조 범위

- AI는 **이미 만들어진 초안을 읽고 준비 안내만** 작성한다. 전체 안내 1개와 일차별 안내 1개씩을 받는다.
- 시각·장소·순서·이동시간은 서버가 만든 값을 그대로 유지한다. AI 응답으로 일정을 바꾸지 않는다.
- 안내는 준비물, 이동 여유, 시간대 주의, 대안 활동처럼 사용자가 미리 준비할 내용을 다룬다.
- 영업시간·휴무·가격·예약 가능 여부·혼잡도·날씨를 확인한 결과가 아니다. 화면에도 같은 문구로 표시한다.
- 자연어 원문, 해석 요약, 계정 식별자, 세션 토큰, DB 키워드 ID는 GPT 요청에 넣지 않는다. 지역·기간·인원·숙박 여부·이동수단·계절/동행/테마 키워드 이름과 일정의 장소 이름·시각만 보낸다.

## 검증과 자기수정

- `json_schema` strict로 응답 형식을 고정하고, 서버가 다시 검사한다. 일차 수와 일차 번호가 초안과 같아야 하며 같은 번호를 두 번 쓸 수 없다.
- 문구는 1~600자의 일반 텍스트만 받는다. HTML 표시(`<`, `>`), 링크(`http`), 연락처(`@`)가 있으면 거부한다.
- 형식이 맞지 않으면 **고정된 한국어 사유**를 전달해 다시 요청한다. 자기수정은 요구분석서 3.1의 제한에 맞춰 최대 2회이며, AI 응답 원문을 다시 보내지 않는다.
- 설정 없음·인증·사용량 제한·연결 실패·시간 초과는 다시 요청하지 않는다. 같은 결과가 나오고 유료 호출만 늘기 때문이다.
- 보조가 실패해도 일정 생성은 실패시키지 않는다. 안내 없이 초안만 제공한다. 전체 보조 예산은 45초이며 남은 시간이 없으면 재요청하지 않는다.
- 저장 직전 검증(`ItineraryGenerator.validate`)에서도 일차 수·번호와 문구 형식을 다시 확인한다. 서버 검사가 AI 설명보다 우선한다.

## 현재 한계와 다음 단계

일정의 조건 충족 여부를 판정하거나 장소를 교체하지 않는다. 요구분석서 3.1의 SFR-04-06 조건 충족 결과 표시와 SFR-04-07 장소 고정·부분 재추천은 이번 범위가 아니다. `시간대별_일정_초안.md`의 "AI 세부 일정 생성·자기수정" 중 **자기수정 제한과 보조 안내**만 연결했고, AI가 일정을 직접 생성하거나 재배치하는 기능은 없다.

안내 문구의 사실 여부는 검증하지 않는다. 형식과 일차 번호만 검사하므로 내용은 참고용이다.

## 확인 결과

- 2026-09-20 SQL Server 프로필 `clean verify` 159개 중 153개 통과, 실제 외부 API 6개는 건너뜀. Jar 빌드까지 성공했다.
- 자동 테스트에서 개인 입력 미전송, 일차 번호 불일치·중복 거부, HTML·링크·연락처·빈 문구·길이 초과 거부, 형식 실패 2회 재요청 후 성공, 3회 실패 시 초안 유지, 인증·한도·예상 밖 오류의 즉시 중단, 이전 작업 JSON 호환을 확인했다.
- 실제 GPT 응답으로 안내 품질을 확인한 기록은 아직 없다. 실물 브라우저 전체 흐름도 미검증이다.
