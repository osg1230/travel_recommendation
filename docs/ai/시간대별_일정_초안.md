# 이동시간을 반영한 일정 초안

## 사용 흐름

추천 완료 → 지역 선택하고 장소 보기 → **하루 시간을 정하고 일정 초안 만들기** → 시작·종료 시간, 이동수단, 관광지 체류시간 입력 → 작업 상태 → 날짜별 일정 초안 확인.

SQL Server 프로필과 001~007 SQL, `KAKAO_REST_API_KEY`가 필요하다. 추가 SQL·테이블 변경은 없다. 최신 Jar로 서버를 재시작해야 한다. 일정 생성 단계에는 GPT를 추가 호출하지 않고, 기존 GPT 추천에서 선택한 지역의 검증된 후보를 서버 규칙으로 배치한다. 카카오 API 사용량은 발생한다.

## 배치와 검증

- 확정한 기간·날짜·숙박 여부·이동수단을 유지한다. 기간 미정 또는 여러 날 여행의 숙박 여부 미정이면 조건 수정을 안내한다. 이동수단 미선택일 때는 입력 화면에서 자동차/대중교통을 선택한다.
- 하루 08:00~21:00 사이 최소 4시간, 관광지별 30~180분을 입력한다. 기본값은 09:00~18:00·90분이며 화면에 표시한다. 모든 날짜에 동일하게 적용한다.
- 2026-09-20부터 외부 조회로 후보를 보충하면 1~7일을 지원한다. 날짜 수×2, 전체 최대 8곳을 선택하며 입력 화면에 이름을 표시한다. 선택한 관광지보다 많은 날짜를 요청하면 거부한다. 관광지를 중복 방문시키거나 가상의 장소로 채우지 않는다.
- 도로명 주소의 건물번호까지 분리하여 카카오 응답과 대조한다. 좌표가 가까운 관광지를 순차 선택하고 날짜별로 나눈다. 첫 장소는 후보 순서를 사용하며 전역 최단 경로 또는 조건별 최적화를 보장하지 않는다.
- 날짜마다 관광·식사(60분)를 포함한다. 점심 이전에 관광을 마치면 식사 전 자유시간을 표시한다. 음식점은 직전 관광지와 직선거리상 가까운 후보, 숙소는 첫 후보를 사용한다. 식당은 날짜별로 반복될 수 있다. 예산·취향 적합도 비교 완료로 표시하지 않는다.
- 이동은 선택한 교통수단의 카카오 경로 소요시간(초)을 분으로 올리고 여유 10분을 더한다. 같은 좌표의 서로 다른 장소는 API 시간을 만들지 않고 ‘같은 주소 내 이동 여유 5분’으로 명시한다. 식당·숙소가 같은 건물인 경우를 포함한다.
- 숙박이 필요하면 마지막 날을 제외한 날의 끝에 숙소 도착·휴식 30분을 넣고 다음 날 숙소에서 출발하는 이동을 포함한다. 이는 객실 이용·체크인 가능 시각 검증이 아니다.
- 모든 항목의 시작·종료 시각, 날짜 수, 관광지 중복/누락, 이동 확보, 음식점·숙소 후보 포함 여부를 생성 후와 저장 직전에 검사한다. 한 구간 이동이 2시간을 넘거나 하루 종료 시간을 넘으면 충돌 안내와 조정 방법을 반환한다.

## 작업·접근 제어

`ai_jobs.job_type=ITINERARY`의 기존 설계를 사용한다. 추천 작업과 큐·결과 역직렬화를 분리한다. `QUEUED → GENERATING_SCHEDULE → VALIDATING_SCHEDULE → COMPLETED`이며 실패 시 `FAILED`가 된다. 여기서 COMPLETED는 **일정 초안 계산 완료**이며 영업·가격 검증 완료를 의미하지 않는다. 검증 단계와 완료는 동일 DB 트랜잭션이라 폴링에서 검증 단계가 보이지 않을 수 있다.

생성 POST는 서버 입력 스냅샷을 커밋한 뒤 HTML 요청에 303, JSON 요청에 202를 반환한다. 화면은 기본 HTML 제출 후 상태를 2초 간격으로 최대 120초 확인하고 완료 시 새로고침한다. 동일 폼 토큰 재전송은 기존 작업을 반환한다. 새 입력 화면을 열면 토큰을 새로 발급하며 이전 탭의 폼은 만료된다. 재생성은 명시적으로 시간 입력 화면을 다시 열어 새 작업을 만든다.

회원 본인/ACTIVE 상태 또는 비회원 세션 해시·만료·작업 유형을 조회마다 검사한다. 외부 API 호출 중에는 DB 트랜잭션을 유지하지 않는다. 작업 대기 2분·완료 2분 제한과 API 호출 사이 110초 제한을 적용하며 재시작 중단 작업은 FAILED로 복구한다. 완료 직전 활성 장소·이름·주소·출처·확인일과 계정 상태를 다시 확인한다. 실패 원문·API 키는 결과에 저장하지 않는다.

작업의 만료는 부모 추천 작업의 만료를 이어받는다. 회원·비회원 모두 이 화면은 임시 초안이며 `itineraries`에 영구 저장하는 기능은 아직 연결하지 않았다. 단일 서버 실행기 기준으로 다중 서버·부하 환경은 검증하지 않았다.

## 현재 한계와 다음 단계

2026-09-20 추가: 장소 목록의 **관광공사 운영정보 확인**으로 조회한 정보는 새 일정에 포함한다. 단순 운영시간·정기휴무와 명확히 충돌하면 생성을 거부하고, 조회 없음·날짜 미정·오래된 정보·복합 예외는 확인 필요로 표시한다. 생성 후와 완료 저장 직전에 검사하며 장소 운영정보가 중간에 바뀌면 다시 생성을 안내한다. [TourAPI 연결 범위](TourAPI_설정.md)에 지원 형식·한계를 정리했다. 자동 재배치나 모든 운영 예외 검증은 포함하지 않는다. 아래 영업정보 미확인 설명은 이 제한적 검사 범위를 제외한 항목에 적용한다.

영업시간·휴무·가격·예산·객실 예약, 출발지↔여행 지역 왕복은 확인하지 않는다. 표시된 마지막 활동 이후에는 별도 일정이 없으며 초기 장소 수 때문에 하루 전체를 채우지 않을 수 있다. 지도는 좌표 위치 링크이고 경로 선·지도 마커 UI는 아직 없다. 체류시간은 계획값, 이동시간은 조회 시점 예상값이다.

이번 구현은 요구분석서 3.1의 SFR-04-03·04 중 시간 입력·서버 배치·동선/시간 검사와 임시 결과 조회 단계다. AI 세부 일정 생성·자기수정, 휴무/운영시간 검사, 예산·취향별 장소 선택, 장소 고정/부분 재추천까지 완료한 것이 아니다. 확인하지 않은 항목을 ‘확인 필요’로 표시한 초안으로 제공한다. 다음 기능은 실제 장소 후보 확충·운영정보 확보와 조건 적합도 검증을 거쳐 AI 일정 보조·저장 기능으로 이어간다.

## 확인 결과

- 2026-09-20 외부 조회 후보·좌표 사용과 3일 일정 DB 통합 검증을 추가했다. 전체 127개 중 122개 통과, 선택형 API 5개 건너뜀. 카카오 후보는 확인 후 24시간 이내 좌표를 사용하며 별도 주소 조회를 생략한다. 상세 범위와 검증은 [외부 장소 조회](외부_장소_조회.md)를 따른다. 아래는 이전 단계의 확인 기록이다.

- 2026-09-18 Java 21·실제 SQL Server에서 전체 Maven verify와 Jar 빌드 성공. 총 118개 중 115개 통과, 외부 API 선택형 3개 건너뜀. 신규 일정 자동 테스트 12개(배치 6, DB·화면 6)를 포함한다.
- 2026-09-19 중단 재개 후 `ItineraryLiveTests`를 별도 실행해 카카오 실제 주소 3곳·자동차 경로 3구간을 조회하는 강릉 2일 일정을 검증했다. 1개 통과. 키를 출력하지 않았다. 이 테스트는 DB·GPT를 사용하지 않는다.
- DB 통합 테스트에서 작업 저장·큐 분리·중복 획득/제출·다른 세션 차단·만료·장소 변경·늦은 응답·재시작 복구·Thymeleaf 결과 렌더링을 확인했다. DB 변경은 롤백했다.
- 실제 DB 후보와 지도 mock으로 렌더링한 입력·결과 HTML을 브라우저에서 확인했다. 기본 뷰포트와 390px 너비의 화면 배치·줄바꿈을 확인했다. 실제 브라우저에서 새 추천부터 GPT·카카오를 함께 호출하는 전체 흐름은 수행하지 않았다.

실제 일정 API 검사는 `RUN_KAKAO_ITINERARY_TESTS=true`와 `KAKAO_REST_API_KEY`를 설정한 뒤 `./mvnw.cmd '-Dtest=ItineraryLiveTests' test`로 실행한다. 일반 테스트에서는 이 테스트가 추가로 건너뛰어지며 반복 실제 호출을 원하지 않으면 실행 후 `RUN_KAKAO_ITINERARY_TESTS`를 제거한다.
