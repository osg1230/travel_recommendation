# 추천 지역 선택과 실제 장소 후보 조회

기준일: 2026-09-18 (한국 시간)

## 구현 범위와 사용 흐름

조건 확정 → 여행지 후보 찾기 → GPT 추천 받기 → **강릉·부산·경주 중 선택하고 장소 보기** → 관광지·음식점·숙소 후보 확인.

지역 선택은 `GET /travel/recommendations/{jobId}/destinations/{destinationId}/places`로 조회한다. 선택한 지역은 URL로 구분하므로 새로고침·뒤로가기·여러 탭의 선택이 서로 덮어쓰지 않는다. 회원 이력에 선택 지역을 영구 저장하거나 일정 작업을 생성하는 단계는 아니다. 앞으로 일정 생성 요청을 받을 때도 이 작업·지역 조합을 재검증해야 한다.

서버는 기존 작업 조회의 회원 소유권·계정 상태 또는 비회원 세션 토큰·보존 만료를 먼저 검사한다. 완료된 추천 목록에 포함된 지역만 선택할 수 있으며, 현재도 활성 DESTINATION이고 이름·지역이 스냅샷과 같아야 한다. 다른 지역 ID 위조·추천 전 접근·비활성 지역을 거부한다. 선택 화면은 응답 캐시를 금지한다.

`PlaceCandidateService`가 현재 지역과 정확히 같은 `places.region`의 활성 장소를 조회하고 DTO로 전달한다. 이름·주소·출처 확인 시각이 없거나 미래 확인일, 허용한 공식 도메인의 HTTPS가 아닌 출처는 제외한다. 서비스에 출처 호스트 목록을 명시했다. 새 출처 도입 시 데이터와 허용 목록을 함께 검토해야 한다. 동일 도메인에 있다는 사실만으로 콘텐츠 진위를 자동 검증하는 기능은 아니다.

숙소는 확정 기간이 2일 이상이고 숙박 불필요를 선택하지 않은 경우에 표시한다. 기간 미정이면 숙소 필요 여부를 확정할 수 없다고 안내한다. 음식점·관광지·숙소는 종류별로 표시하고 빈 결과와 DB 조회 실패를 구분한다. DB 오류를 예시 데이터로 대체하지 않는다.

## 초기 데이터와 확인 범위

기존 SYSTEM 지역 데이터와 같은 방식으로 공식 출처를 확인해 저장한 장소 12곳을 사용한다. 매 요청마다 외부 관광 API를 호출하지 않는다. `verified_at`은 출처 확인 시각인 2026-09-17 15:25 UTC(한국 시간 9월 18일)이며, 원문 게시일이나 최신 영업 상태를 보장하는 값이 아니다. 검색 색인에서 확인한 페이지도 포함한다.

| 지역 | 관광지 | 숙소 | 음식점 |
| --- | --- | --- | --- |
| 강릉 | 오죽헌·시립박물관, 경포대 | 씨마크 호텔 | 씨마크 호텔 더 레스토랑 |
| 부산 | 해운대해수욕장, 감천문화마을 | 신라스테이 해운대 | 해운대암소갈비집 |
| 경주 | 황리단길, 동궁과 월지 | 라한셀렉트 경주 | 마켓338 |

개별 출처 URL은 [007 SQL](../database/sql/007_seed_local_places.sql)의 각 행에 보관하며 화면에서도 직접 연결한다. 주요 출처는 [오죽헌·시립박물관](https://www.gn.go.kr/museum/contents.do?key=886), [한국관광공사 경포대](https://english.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=110841), [비짓부산 해운대](https://www.visitbusan.net/index.do?lang_cd=ko&menuCd=DOM_000000201001001000&uc_seq=373), [경주문화관광 동궁과 월지](https://search.gyeongju.go.kr/tour/page.do?area_uid=50&cmd=2&code_uid=1012&listType=&mnu_uid=2292&sortKwd=&srchKwd=), 각 호텔·음식점 공식 사이트이다.

확인한 항목은 장소 이름·주소·유형과 짧은 소개다. 가격·객실 가용성·영업시간·좌표·교통시간은 검증하지 않았으며 `latitude`, `longitude`, `details_json`, `map_url`을 임의로 채우지 않는다. 숙소가 호텔 1곳씩인 작은 후보 집합이므로 예산·취향·동선에 최적인 추천으로 표시하지 않는다. 지도 검색 링크는 서버가 이름과 주소를 인코딩해 [Kakao 공식 지도 URL 형식](https://apis.map.kakao.com/web/guide/#routeurl)에 맞춰 만든다. 확정 좌표·경로 안내와 구분한다.

## PC별 적용

001~006 SQL을 적용한 DB에서 다음을 실행한다. 다른 PC의 DB는 Git pull로 갱신되지 않는다.

```powershell
sqlcmd -S localhost,1433 -E -C -d travel_recommendation -b -f 65001 -i docs/database/sql/007_seed_local_places.sql
```

기존 데이터와 스키마를 변경하지 않고 없는 SYSTEM 식별자만 추가한다. 이번 PC에서는 최초 12행, 재실행 0행을 확인했다. JPA 자동 DDL은 none이다.

## 요구사항과 설계 대조

요구분석서 3.1 통합본의 SFR-03-06(지역 선택), SFR-04-02(관광지 조회)를 연결했다. SFR-05-01·03의 숙박 여부·숙소 기본 정보는 일부 반영했지만 동선에 맞는 숙소 추천(SFR-05-02)은 아직 아니다. 지도 검색 링크만 제공하므로 지도 마커·길찾기·동선 표시 요구사항 전체를 완료로 기록하지 않는다.

DB 정의서 7절과 ERD의 `places` 컬럼·유형을 그대로 사용한다. 새 테이블·컬럼·관계는 없다. 선택한 지역 ID를 담는 별도 저장 필드를 임의로 만들지 않았다. 기존 화면 추적표는 과거 요구사항 기준이므로 이번 구현 대조만 추가하고 전체 정합성 완료로 취급하지 않는다.

## 검증 및 다음 작업

`PlaceCandidateIntegrationTests`는 실제 SQL Server에서 세 지역 조회·화면 렌더링, 추천 결과 링크, 회원·비회원 소유권, 제한 계정, 만료, ID 위조, 미완료·비활성 지역, 숙박 제외, 안전하지 않은 출처·미확인 주소·미래 확인일 제외, 빈 결과를 검사한다. 변경은 롤백하며 GPT 유료 호출 없이 추천 완료 상태를 준비한다.

`PlaceCandidateControllerTests`는 DB 오류 정보 비노출과 HTML 이스케이프·목록 중복 표시 여부를 검사한다. `-Dtravel.ui.capture=true`로 통합 테스트를 실행하면 `target/ui-check`에 실제 Thymeleaf 응답을 저장해 화면 점검에 활용할 수 있다. 테스트 결과 상세는 [진행 문서](../progress.md)를 따른다.

다음 작업은 일정 생성 전의 여행 기간·하루 이용 가능 시간 확인, 장소 좌표 확보와 이동수단별 이동시간 검증 기준 결정이다. 이후 가까운 장소 묶기·방문 순서·체류/식사/휴식 시간 배치와 일정 검증을 구현한다. 현재 후보 수로 긴 여행 일정을 억지로 채우거나 검증하지 않은 이동시간을 사실로 표시하지 않는다.
