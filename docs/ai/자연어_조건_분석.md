# GPT 자연어 조건 분석과 조건 확정

구현 기록: 2026-09-11 · 문서 기준 갱신: 2026-09-13

[요구분석서 적용 기준](../requirements/적용기준.md)을 따른다. 형식 오류 자동 재요청과 WebClient 비동기 전환은 아직 구현하지 않았다. 아래의 수동 재시도는 현재 동작 설명이다.

## 구현 범위

요구분석서 SFR-02-01~04, SFR-03-01 및 UC-06의 조건 분석·보완·확정 부분이다. GPT가 입력 문장에서 조건을 추출하고 서버가 응답을 검증한 뒤 사용자가 직접 수정한다. 확정 조건은 현재 세션에만 보관한다. 이후 recommendation_requests·ai_jobs 저장과 지역 후보 추천은 연결했다([여행지 후보 조회](여행지_후보_조회.md)). 상세 일정 생성은 다음 단계다. DB 테이블·컬럼은 이번에 변경하지 않았다.

GPT는 실제 장소나 운영시간을 검증하지 않는다. 세부 지역명은 예를 들어 강릉을 강원으로 축소하지 않고 보존하며, 실제 국내 장소 여부는 이후 외부 장소 조회에서 확인한다.

## 화면 흐름

| 요청 | 처리 |
| --- | --- |
| POST /travel/conditions | 기존 입력 검증·임시 보관. 성공하면 이전 분석·확정 조건을 무효화 |
| GET /travel/conditions/check | 원문 또는 선택 조건 확인 |
| POST /travel/conditions/analyze | 세션의 원문 한 건을 GPT에 보내 분석. 요청의 draftId와 현재 입력 비교 |
| GET /travel/conditions/review | 분석 결과 또는 선택 조건을 보완. 새로고침으로 API를 호출하지 않음 |
| POST /travel/conditions/confirm | 최신 수정 토큰과 모든 조건을 검증한 뒤 세션에 확정 조건 저장 |
| GET /travel/conditions/confirmed | 확정 결과 확인 및 수정 복귀 |

회원·비회원 모두 이용할 수 있다. 모든 POST는 CSRF 보호를 유지한다. 키워드 입력은 GPT 호출 없이 보완·확정할 수 있다. 분석 중 안내와 버튼 중복 클릭 방지를 제공하고 JavaScript가 없어도 POST와 서버 검증은 동작한다.

## 설정과 호출

- 제공자: OpenAI Responses API (`https://api.openai.com/v1/responses`). 서버에서만 호출한다.
- 초기 조건 추출 모델: `gpt-4.1-mini`. `OPENAI_MODEL` 환경변수로 변경할 수 있다. 일정 생성 모델의 품질·비용 비교까지 완료한 선택은 아니다.
- 인증키: `OPENAI_API_KEY` 우선, 없으면 기존 `Portfolio_java_API` 환경변수를 사용한다. 실제 값은 Git·화면·로그에 기록하지 않는다. 기본 프로필도 키가 있으면 실제 유료 분석을 실행한다.
- 서버 연결 제한 5초, 전체 요청 제한 25초, 출력 토큰 상한 1,800. 타임아웃·인증 오류·429·서비스 장애·거절·불완전 응답·잘못된 JSON은 고정 안내를 반환한다.
- 자동 유료 재시도는 없다. 오류 후 사용자가 다시 요청할 수 있다. 같은 세션의 동시 분석은 한 건만 허용한다. 성공한 현재 입력은 재사용하며, 입력을 다시 제출하면 새 분석 대상으로 처리한다.
- `store=false`로 Responses API의 응답 저장을 요청하지 않는다. 이 설정을 모든 제공자 보존 정책이 해제된 것으로 간주하지 않는다.
- AI에 전달하는 데이터는 원문·한국 기준 날짜·활성 선택지의 표시명과 선택값이다. 로그인 정보·회원 식별자·비밀번호·DB 접속정보는 추가하지 않는다. 원문에 개인정보를 넣지 않도록 전송 전 화면에서 안내한다.

## 응답·조건 검증

정해진 JSON Schema의 모든 필드를 요구하고 추가 필드를 거부한다. 계절·동행자·취향·이동수단의 출력은 요청 당시 활성 선택값을 enum으로 제한한다. 모델에 DB 명칭·운영 코드·선택 ID를 함께 보내 생길 수 있는 혼동을 줄이기 위해 표시명과 선택값만 전달한다.

서버에서도 필드 누락·추가, 자료형, 지역 100자, 해석 안내 1,000자, 활성 선택지·카테고리, 유효한 날짜와 날짜 쌍, 일수 일치, 예산·인원 범위를 다시 검사한다. 실패 시 원문이나 응답값 대신 실패 필드 이름만 로그에 남긴다. 분석 결과 자체가 여행 의도를 정확히 해석했는지는 사용자의 보완·확정으로 확인한다.

- 미정 값은 null 또는 빈 배열로 유지한다. 날짜·일수·인원을 임의로 확정하지 않는다.
- 일수와 예산은 기존 검증 범위를 유지한다. 인원은 현재 입력 기준으로 1~32,767 정수를 허용하며 아직 DB 컬럼 제약을 추가하지 않는다.
- 숙박 필요·주변 지역 포함은 미정/예/아니오로 구분한다.
- 확정 결과는 날짜·정수·금액·Boolean으로 변환하고 선택 당시 ID·카테고리·이름·값을 보관한다.
- 분석 응답을 기다리는 동안 입력이 바뀌면 이전 결과를 버린다. 로그아웃한 세션을 되살리지 않는다. 새 입력과 확정 시 토큰을 갱신해 이전 탭의 제출이 최신 조건을 덮어쓰지 않게 한다.
- 원문·분석 안내·지역명을 Thymeleaf의 이스케이프 출력으로 표시한다.

## 검증 방법

`ConditionReviewTests`는 가짜 AI 응답으로 분석→보완→확정, 누락 조건, 위조·오류, 세션 분리, CSRF, 이전 토큰, 동시 요청과 오래된 응답 폐기를 검사한다. `OpenAiConditionClientTests`는 로컬 HTTP 서버로 요청 형식·출력 enum·저장 설정·오류·거절·타임아웃을 검사하므로 실제 API 사용료가 발생하지 않는다.

실제 호출은 `RUN_OPENAI_TESTS=true`일 때만 `OpenAiLiveTests`에서 예시 한 건으로 실행한다. 키워드 SQL이 적용된 SQL Server와 Windows 인증 DLL이 필요하다. 테스트 실행 환경에 키를 먼저 주입하고 다음과 같이 실행한다.

```powershell
. ./scripts/use-java21.ps1
$env:RUN_OPENAI_TESTS = 'true'
$jdbcAuthPath = Join-Path $env:USERPROFILE '.m2/repository/com/microsoft/sqlserver/mssql-jdbc_auth/13.4.0.x64'
try {
    ./mvnw.cmd test '-Dtest=OpenAiLiveTests' "-DargLine=-Djava.library.path=$jdbcAuthPath"
} finally {
    Remove-Item Env:RUN_OPENAI_TESTS
}
```

2026-09-11 실제 호출에서 강릉·3일·2명·총예산 60만 원·숙박 필요·날짜 미정을 검증했다. 최초 호출은 조건 검증에서 거부됐고, 선택값 enum 제한과 전송 선택지 정리 후 재검증에 성공했다. 최초 응답값을 보관하지 않아 어떤 필드가 실패했는지는 사후 확정하지 않았다. 실제 호출은 총 2건이며 다양한 여행 문장에 대한 품질 평가를 완료한 것은 아니다.
