# 열차 이동시간·버스·기차 탭 계획 (2026-11-03 확정, 미착수)

대중교통 일정에 KTX 등 열차를 반영하는 계획이다. 노트북에서 API 확인과 결정만 했고, 구현은 데스크탑에서 한다. 구현 브랜치는 `feature/train-travel-time`으로 정했다.

## 왜 필요한가

- 2026-11-03 카카오 대중교통 길찾기는 서울역→부산역, 서울역→강릉역 모두 `NO_RESULTS`였다(두 구간만 확인).
- `HomeTripService`는 이때 직행 시외·고속버스로 넘어가므로, 이런 장거리 구간은 KTX가 빨라도 버스 기준으로 계산될 가능성이 높다. 버스 시간에는 집↔터미널 이동이 빠져 있고, 직행 버스가 없으면 시간을 찾지 못한다.

## API 확인 결과

- 대상: 공공데이터포털 [국토교통부_(TAGO)_열차정보](https://www.data.go.kr/data/15098552/openapi.do). 2026-11-03 사용자가 활용신청을 마쳤다.
- 주소: `https://apis.data.go.kr/1613000/TrainInfo/GetStrtpntAlocFndTrainInfo`. `TrainInfoService` 주소는 400이었다.
- 인증키: `TOUR_API_SERVICE_KEY`로 호출했다. `travel.tago.service-key`가 이 값을 쓴다.
- 요청: `serviceKey`, `_type=json`, `depPlaceId`, `arrPlaceId`, `depPlandTime=YYYYMMDD`, `pageNo`, `numOfRows`, 선택 `trainGradeCode`. 예: 서울 `NAT010000`, 부산 `NAT014445`.
- 응답 항목: `trainno`, `traingradename`, `depplacename`, `arrplacename`, `depplandtime`, `arrplandtime`, `adultcharge`.
- 서울→부산 결과: 11/3과 11/10은 75편(KTX 계열 55, ITX-새마을 10, 무궁화호 7, ITX-마음 3), 40일 뒤인 12/13은 0편이다. 첫 KTX는 05:13 → 07:50, 59,800원이었다.
- 모르는 것: 조회 가능 일수의 정확한 끝(7일 뒤와 40일 뒤 사이로 보인다). 한 구간만 확인했다. 시·도별 기차역 목록 오퍼레이션은 아직 호출하지 않았다.

## 결정

- 새 이동수단 키워드 `기차`를 추가하지 않는다. 대중교통 안에서 집↔여행지 시간의 근거로 쓴다.
- 일정 시간은 `집→역 이동 + 승차 대기 + 열차 + 역→관광지 이동`을 구해 버스와 비교하고 더 빠른 수단을 쓴다. 대기시간 값은 구현 때 정한다.
- 여행 날짜 시간표를 먼저 보고, 비어 있으면 오늘 시간표의 소요시간을 쓰며 근거에 '오늘 운행 기준'이라고 적는다.
- 결과 화면의 `버스로 가는 방법`을 `대중교통으로 가는 방법`으로 바꾸고 버스·기차 탭을 둔다.
- 탭은 안내용이다. 탭을 바꿔도 일정 시간은 바뀌지 않는다. 일정에 쓴 수단의 탭에 `일정 기준`을 표시하고 먼저 연다.
- 찾기 버튼 하나로 버스와 기차를 함께 조회하고 10초 재조회 제한을 유지한다.
- 기차는 종류별로 묶어 횟수, 첫차, 막차, 최단 소요, 최저 요금을 보여 준다. 편별 나열은 하지 않는다.
- 한쪽 결과가 없어도 탭을 유지하고 그 탭에 찾지 못했다고 안내한다.

## 구현 범위

- 새 클래스: `TrainClient`(`FlightClient`와 같은 방식), `TrainGuideService`(`FlightGuideService`와 같은 구조).
- 수정: `HomeTripService`, `ItineraryController`의 안내 조회, `itinerary-result.html`(기존 `.region-tab` 재사용), `home-trip.html` 안내 문구.
- 역 찾기: 시·도별 기차역 목록으로 출발지와 여행지에서 가까운 역을 찾는다. 역 좌표를 받을 수 있는지는 구현 전에 확인한다.
- 문서: 요구분석서 SFR-06-02 변경 내역과 이 문서, 진행 기록.
- 확인: `TrainClient` 단위 테스트, PC·휴대폰 너비 탭 화면, 실제 API 호출 한두 구간.

## 범위 밖

`기차` 키워드 추가, 좌석 잔여 조회, 실제 예매, 탭 선택에 따른 일정 재계산, 여행지 내부 이동의 열차 반영, DB 변경.
