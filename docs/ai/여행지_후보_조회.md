# 확정 조건 → 추천 작업 → 여행지 후보

기준일: 2026-09-12

## 현재 구현 범위

여행 조건을 확정한 후 **여행지 후보 찾기**를 누르면 회원 추천 요청과 회원·비회원 작업을 DB에 저장한다. 별도 실행기가 활성 지역 후보를 조회하고 화면에서 출처와 확인일을 보여 준다.

후보 준비 후 **GPT 추천 받기**를 누르면 확정 조건으로 추천 순위·이유를 생성하고 검증·저장한다. 후보 조회 자체는 무료 API 미호출이며 GPT 추천 버튼에서 유료 호출이 발생한다. 2026-09-18부터 추천 지역 선택 후 [개별 관광지·숙소·음식점 조회](지역별_장소_조회.md)를 제공한다. 시간대별 일정, 저장 일정과 추천 이력 목록 UI는 아직 없다.

## 데이터 출처

다음 공식 관광 사이트에서 2026-09-11 지역명과 간단한 관광 소개를 확인해 places의 SYSTEM 데이터로 저장했다. 매 요청 시 웹사이트나 지도 API를 호출하는 실시간 수집은 아니다. 관리자가 장소를 CRUD하는 화면은 제공하지 않는다.

| 지역 | 공식 출처 | 확인 범위 |
| --- | --- | --- |
| 강릉 | [비짓강릉](https://visitgangneung.net/) | 바다·커피, 자연·문화 관광 소개 |
| 부산 | [비짓부산](https://www.visitbusan.net/kr/index.do) | 해변·도심·음식·문화 관광 소개 |
| 경주 | [경주문화관광](https://gyeongju.go.kr/tour/index.do) | 역사 유산·도보·자전거 여행 소개 |

좌표·가격·영업시간·교통시간은 검증하지 않아 넣지 않았다. 2026-09-22부터 SQL 014로 전국 17개 시·도 여행지 28곳을 쓴다. 시·도 이름(강원·경북 등)이면 그 시·도의 여행지 전체, 여행지·시군 이름(강릉·강릉시·강원도강릉시)이면 그곳만 조회한다(`Provinces`가 강원특별자치도·강원도·강원 같은 표기를 하나로 맞춘다). 광주·전남은 2026-07-01 통합된 전남광주통합특별시의 여수·순천·담양으로 찾는다. GPT가 한 번에 5곳만 비교하므로 후보가 5곳보다 많으면(지역 미지정 등) 여행 취향과 겹치는 분류(subtype)가 많은 곳부터, 지역 미지정이면 시·도마다 한 곳씩 먼저 골라 5곳을 넘기지 않는다. 지역을 넓혀 결과를 채우지 않는다. 상세 지역·다중 지역 해석과 주변 지역 1~2시간 이동 검증은 후속 작업이다.

## PC별 DB 적용

001~003이 적용된 DB에서 아래 명령을 순서대로 실행한다. 이 데스크탑에는 적용했다. 다른 PC의 DB는 Git pull로 갱신되지 않는다.

```powershell
sqlcmd -S localhost,1433 -E -C -d travel_recommendation -b -f 65001 -i docs/database/sql/004_create_recommendation_jobs.sql
sqlcmd -S localhost,1433 -E -C -d travel_recommendation -b -f 65001 -i docs/database/sql/005_seed_destinations.sql
sqlcmd -S localhost,1433 -E -C -d travel_recommendation -b -f 65001 -i docs/database/sql/006_create_recommendation_results.sql
```

004와 006은 각각 한 번만 적용한다. 기존 대상 테이블이 있으면 중단하므로 재생성하거나 삭제하지 말고 스키마를 확인한다. 005는 재실행해도 기존 데이터를 덮어쓰지 않는다. JPA 자동 DDL은 계속 none이다. 이미 004·005가 있다면 006만 적용한다.

## 실행과 화면 테스트

실행 중인 이전 Jar는 Ctrl+C로 종료한 다음 빌드한다.

```powershell
. .\scripts\use-java21.ps1
.\mvnw.cmd "-Dmaven.repo.local=$env:USERPROFILE/.m2/repository" package -DskipTests
$jdbcAuthPath = Join-Path $env:USERPROFILE '.m2/repository/com/microsoft/sqlserver/mssql-jdbc_auth/13.4.0.x64'
java "-Djava.library.path=$jdbcAuthPath" -jar target/travel_recommendation-0.0.1.jar --spring.profiles.active=sqlserver-windows
```

1. http://localhost:8080/travel/conditions → 조건 고르기 → 확인 → 보완 → 확정.
2. **여행지 후보 찾기** → 잠시 후 지역 후보·공식 출처·확인일 표시. GPT API 키 없이 키워드 입력으로 테스트할 수 있다.
3. 보완 화면에서 강릉 입력 시 강릉만, 지역을 비우면 3곳, 제주 입력 시 지원 지역과 수정 안내가 나오는지 확인한다.
4. 같은 확정 화면에서 다시 제출하면 같은 작업 주소로 이동한다. 입력을 수정하고 다시 확정하면 새 작업이다.
5. 다른 시크릿 창으로 작업 주소를 열면 404이며 결과가 보이지 않아야 한다.
6. 실패 화면의 재조회는 현재 확정 조건으로 새 요청을 만든다. 지역 미지원은 먼저 지역을 수정해야 해결된다.

## 자동 테스트

```powershell
. .\scripts\use-java21.ps1
$env:RUN_SQLSERVER_TESTS = 'true'
$env:RUN_OPENAI_TESTS = 'false'
$env:RUN_OPENAI_RECOMMENDATION_TESTS = 'false'
$jdbcAuthPath = Join-Path $env:USERPROFILE '.m2/repository/com/microsoft/sqlserver/mssql-jdbc_auth/13.4.0.x64'
.\mvnw.cmd "-Dmaven.repo.local=$env:USERPROFILE/.m2/repository" "-DargLine=-Djava.library.path=$jdbcAuthPath" verify
```

RecommendationJobIntegrationTests는 실제 SQL Server에서 생성·스냅샷·중복·CSRF·회원/비회원 소유권·제한 계정·지역 불일치·비활성/잘못된 출처·만료·재시작 복구·대기 시간 초과를 검사한다. 변경 데이터는 롤백한다. Maven 테스트에서는 자동 실행기를 꺼서 테스트 트랜잭션 밖의 작업을 처리하지 않도록 한다.

처리 상태는 QUEUED → SEARCHING_CANDIDATES → CANDIDATES_READY 또는 FAILED이다. 후보 준비에서 폴링을 멈추고 **GPT 추천 받기**를 누르면 RECOMMENDATION_QUEUED → RANKING_CANDIDATES → COMPLETED 또는 FAILED로 이어진다. 성공 시 순위·이유·공식 출처를 표시한다.

## GPT 추천 테스트

- 서버 실행 터미널에 OPENAI_API_KEY 또는 Portfolio_java_API 환경변수가 있어야 한다. 키 값을 소스나 문서에 넣지 않는다. 모델은 OPENAI_MODEL, 기본 gpt-4.1-mini이다.
- 강릉 조건은 강릉 1개만 추천하며, 지역 미지정은 초기 후보 3개를 비교한다. AI가 후보를 새로 만들거나 누락·중복하면 거부한다. 가격·영업·이동시간을 실시간 검증한 추천은 아니다.
- 실패 시 같은 작업에서 최대 3회까지 직접 재시도한다. 완료 후 다시 눌러도 유료 호출을 반복하지 않는다. 후보 정보 변경 오류는 조건 화면에서 후보를 다시 조회한다.
- 실제 유료 테스트는 아래 명령에서 한 번 호출한다. 일반 verify에서는 두 종류의 실제 OpenAI 테스트를 모두 건너뛴다.

```powershell
$env:RUN_OPENAI_RECOMMENDATION_TESTS = 'true'
.\mvnw.cmd "-Dmaven.repo.local=$env:USERPROFILE/.m2/repository" "-DargLine=-Djava.library.path=$jdbcAuthPath" '-Dtest=OpenAiRecommendationLiveTests' test
$env:RUN_OPENAI_RECOMMENDATION_TESTS = 'false'
```

공식 구현 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). 명칭·출처를 모델에게 생성시키지 않고 후보 ID와 이유만 받아 서버 데이터와 조합한다.
