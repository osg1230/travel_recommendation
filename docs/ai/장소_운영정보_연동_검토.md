# 장소 운영정보 연동 검토

기준일: 2026-09-20. 출처 조사와 구현 준비 기록이며, 운영정보 조회·일정 검증 구현 완료 문서가 아니다.

후속 결정: 사용자가 TourAPI 연동을 선택했다. [신청·설정 안내](TourAPI_설정.md)에 인증 설정과 소개정보 클라이언트 구현 범위를 기록했다. 아래 출처 조사 당시의 미확인 항목 중 API 주소·요청 파라미터·유형별 운영정보 필드는 공식 Swagger로 추가 확인했다. 실제 표본·DB·일정 연결은 남아 있다.

## 확인한 사실

- [카카오 로컬 API 공식 문서](https://developers.kakao.com/docs/ko/local/dev-guide)의 장소 검색 응답에는 이름·주소·좌표·전화번호·상세 페이지 URL이 있지만 영업시간·휴무 필드는 없다. 카카오 검색 성공이나 상세 링크 제공만으로 운영 여부를 확인했다고 표시할 수 없다.
- [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do)는 관광정보의 검색과 소개정보 조회를 제공하는 공식 연동 후보다. 이번에는 서비스 안내를 확인했으며, 유형별 운영정보 응답 필드·실제 값·누락률·현재 호출 경로와 인증은 아직 검증하지 않았다.
- 현재 `Place.detailsJson`과 DB 정의서의 `places.details_json`은 운영시간·휴무를 담을 수 있지만, `PlaceCandidateService`는 이를 읽지 않고 `PlaceCandidate`에도 해당 정보가 없다. 일정 생성기는 방문 시간과 이동 시간을 검사하며 운영 여부는 검사하지 않는다.
- 저장소 SQL에서 운영정보를 적재하는 구현은 확인하지 못했다. 실제 SQL Server 데이터는 이번에 조회하지 않았다.

## 적용 기준

요구분석서 3.1 통합 변경 내역의 SFR-04-04(운영시간 정보 부족 검증)와 기존 일정 초안 범위에 맞춘다.

1. 운영정보의 출처·원문·확인 시각을 장소 존재 확인 시각과 구분한다. 카카오 장소 갱신으로 운영정보 확인 시각을 갱신하지 않는다.
2. 다른 제공자의 장소는 이름만으로 연결하지 않는다. 주소·좌표·장소 유형을 대조하고 동일 장소인지 모호하면 미확인으로 남긴다.
3. 정보 없음, 출처 불명, 해석 실패, 여행 날짜 미정, 적용 기간 불명은 모두 ‘확인 필요’로 처리한다. 빈 휴무 값을 연중무휴로 해석하지 않는다.
4. 확인된 적용 날짜의 운영 구간 안에 방문 시작부터 종료까지 들어가는지 검사한다. 휴무나 영업시간 밖 방문이 명확하면 충돌을 안내한다. 계절·공휴일·임시 휴무·입장 마감·휴게시간 예외를 해석하지 못하면 확인 완료로 표시하지 않는다.
5. 숙소 체크인 가능 시각은 영업시간과 별개다. 운영정보 확인을 객실 예약 가능 확인으로 표시하지 않는다.
6. GPT가 추측한 시간으로 빈 값을 채우지 않는다. 기존 초안의 ‘확인 필요’ 안내는 실제 검증이 연결될 때까지 유지한다.

## 다음 구현 순서

1. TourAPI 또는 장소 공식 홈페이지 자료 중 최초 적용 출처를 정하고 관광지·음식점·숙소의 소수 표본을 확인한다. API를 선택하면 활용 신청·인증키 설정과 실제 응답 확인이 필요하다. 키는 환경변수 또는 Git 제외 설정으로 관리한다.
2. 표본을 근거로 `details_json` 내 운영정보 형식과 유효기간을 정하고 DB 정의서에 반영한다. 기존 테이블·컬럼 추가는 현재 필요하지 않으며, JSON 구조는 아직 확정하지 않았다.
3. 조회 서비스 → 후보 DTO → 일정 입력 스냅샷 → 생성 후/저장 직전 검증 → 결과 화면 순서로 연결한다. 기존 작업 JSON에 필드가 없는 경우는 미확인으로 취급한다.
4. 운영시간 내 방문, 종료 경계, 휴무, 휴게시간 겹침, 날짜 미정, 누락·오래된 정보·해석 불가, 동일 장소 연결 실패를 테스트한다. DB 조회 및 실제 API 확인은 단위 테스트와 구분해 기록한다.

외부 출처 연동, 데이터 적재, 자동 시간 조정, DB·브라우저·실제 API 검증은 이번 조사에 포함되지 않았다.
