DB 변경 없음. SQL Server 통합 테스트 3개 추가, 전체 239개 중 233개 통과, 실패 0, 외부 API 6개 건너뜀.
- 2026-09-21 주변 지역 추천(SFR-07-01~03): 사용자 선택으로 주변 여행지 데이터를 늘리고 시외버스 API도 함께 연결했다. [012 SQL](database/sql/012_seed_nearby_places.sql)로 여행지 속초·양양·울산과 관광지 6곳(TourAPI로 이름·주소·좌표 확인)을 추가하고 이 PC DB에 적용했다(9행, 기존 데이터 변경 없음). 새 여행지는 첫 추천 후보에 넣지 않는다. 일정 초안 생성 뒤 `NearbyRegionService`가 ① 판단: 조건의 '주변 지역 포함'이면 찾고 '선택 지역 중심'이면 찾지 않으며, 미정이면 하루 종료 시간까지 3시간 이상 빈 날이 있을 때만 찾는다 ② 탐색: 지역별 기준 터미널(카카오로 위치 확인) 사이를 자동차 일정은 카카오 자동차 이동시간, 대중교통 일정은 TAGO 오늘 직행 시외버스 배차로 재어 편도 120분 이내만 남긴다 ③ 추천: 가까운 순 최대 3개 지역과 공식 출처로 넣은 관광지(SYSTEM) 최대 3곳을 일정 초안 화면의 '주변 지역도 둘러보기'에 보여 준다. 일정에 끼워 넣지 않는 참고 추천이며 결과는 작업 JSON(`Result.nearby`)에만 남기고 저장 일정 상세에는 표시하지 않는다. 조회 실패·시간 부족이면 이유만 표시하고 초안은 그대로 제공한다. TAGO는 2026-03 이후 `SuburbsBusInfo/Get...` 주소이며 당일 배차만 주므로 '오늘 운행 기준' 안내를 붙였다(SFR-06-06 문구). 키는 `TAGO_SERVICE_KEY`, 없으면 `TOUR_API_SERVICE_KEY`를 쓴다. 단위 테스트 9개(버스 클라이언트 4·판단/탐색 5) 추가, SQL Server 포함 전체 248개 중 242개 통과, 실패 0, 외부 API 6개 건너뜀. 실제 카카오 키로 부산 일정 초안에서 울산 43분·경주 54분 추천 표시를 브라우저로 확인했다. **TAGO 활용신청이 아직 승인되지 않아(등록되지 않은 서비스키) 실제 시외버스 응답의 필드명·터미널 이름(`busName`)은 확인하지 못했다.** 승인 후 터미널 조회와 배차 필드를 실제 응답과 대조해야 한다.

1. 작업 시작 시 Git 상태와 최신 원격 커밋을 확인한다. Claude와 Codex는 같은 기준 커밋을 사용하며 동일 폴더를 동시에 수정하지 않는다.
2. 운영정보 기본 연결을 완료했다. 사용자 흐름은 장소 목록 → 관광공사 운영정보 확인 → 새 일정 초안 생성이다. 다음 확인은 실제 브라우저 전체 흐름·음식점/숙소 응답 표본이며, 해석 불가 예외는 확인 필요로 유지한다. 이후 AI 일정 보조의 요구사항과 현재 배치 기능 차이를 대조한다.
3. AI 일정 보조의 첫 단계(준비 안내·자기수정 제한), 내 일정 저장·조회·이름 수정·삭제, 즐겨찾기, 관리자 회원 관리의 기본 흐름을 구현·검증했다. 다음은 최신 기능의 main 통합과 일정 내용 수정(SFR-08-04)·조건 충족 표시(SFR-04-06) 보완이다. 취향 탐색·필수/선호 조건 구분(SFR-02-05~07), 자연어 일정 수정, 장소 고정·부분 재추천(SFR-04-07)도 요구분석서와 대조해야 한다. 이름 수정만으로 일정 내용 수정까지 완료했다고 보지 않는다. 장소 평가는 진행 요약과 화면 추적표의 R2 표기가 달라 범위를 정리하고, 예약·결제는 선택 확장으로 유지한다.
4. 요구분석서 3.1과 DB·화면 추적표는 관련 기능 구현 시 해당 부분을 대조한다. 전체 설계 일치 완료로 간주하지 않는다.
