## 1. 프로젝트 개요와 현재 진행상황

자연어 또는 여행 조건을 입력받아 AI와 외부 데이터를 활용해 국내 관광지, 숙소, 음식점을 포함한 여행 일정을 추천하는 웹 서비스이다.

현재 Java 21 기반 Spring Boot 실행, SQL Server Windows 인증 연결, 회원 테이블, 회원가입·로그인·로그아웃과 사용자 정보 조회·수정까지 구현했다. DB 없이 실행하면 기존 확인 화면을 제공하고, `sqlserver` 또는 `sqlserver-windows` 프로필에서 회원가입 화면과 저장 기능을 사용할 수 있다.

최신 상태(2026-09-11): GPT 자연어 분석 → 조건 보완 → 세션 내 확정 흐름을 구현했다. 실제 OpenAI 연결로 예시 문장 분석을 확인했으며 API 설정과 구현 범위는 docs/ai/자연어_조건_분석.md에 기록했다. 다음 단계는 확정 조건을 추천 요청·AI 작업과 외부 장소 후보 조회에 연결하는 것이다. 아래 날짜별 기록은 당시 작업 이력이다.

## 3. 설계 진행상황

아래 작성 이력과 별도로 실제 추가된 문서 위치 및 내용의 일부를 확인했다. 문서 전체가 일치하는 확정 설계로 간주하지 않는다.

### 확인된 문서 위치와 남은 정리

경로는 프로젝트 루트 기준이다.

- 요구분석서: `docs/requirements/`에 `창프2_요구분석서 3.0_관리자범위축소_최종본.docx`를 두고, 나머지 7개 문서는 `docs/requirements/archive/`에 보관했다. 사용자가 이름을 바꾼 `창프2_요구분석서 3.0_최종수정본 아님.docx`도 그대로 보존했다. 관리자 범위 축소본을 우선 참고하되 아래 미해결 정책은 구현 전에 통일해야 한다.
- DB 정의서: `docs/database/DB 테이블 정의서_수정본.docx`, 이전 원본은 `docs/database/archive/DB 테이블 정의서.docx`에 있다. 수정본은 회원 정보를 `login_id`, `password_hash`, `nickname`으로 정의한다. 요구분석서의 닉네임 중복 거부와 DB 수정본의 UNIQUE 제약 부재는 정책 통일이 필요하다.
- ERD: `docs/database/erd/`에 `여행 추천 서비스DB ERD.html`과 `여행 추천 서비스DB ERD_files/`를 함께 보관한다. 실제 관계와 DB 정의서의 전체 대조는 미수행이다.
- 화면 설계: `docs/screens/`에 이미지, `최종_화면_ID_정리.txt`, `화면_흐름도.md`, `화면_요구사항_추적표.md`를 모았다. 전체 문서 위치는 `docs/README.md`에 안내한다.
- 추적표는 현재 없는 `sources/창프2_요구분석서 아마도 최종.docx`와 이전 명세 v1.5를 참조한다. 최신 요구사항 번호와 내용을 대조해 갱신해야 한다. 즐겨찾기 대상도 최신 문서의 여행지·관광지·숙소와 맞춰야 한다.
- 관리자 범위: `AGENTS.md`는 회원 관리만 허용하지만 요구분석서·DB·화면 설계는 키워드 관리도 포함한다. 이번 작업에서는 범위를 변경하지 않았으며, 구현 전 사용자와 범위를 확정하고 관련 문서를 통일해야 한다.

## 5. 현재 기본 패키지 구조

```text
travel_recommendation/
├─ AGENTS.md
├─ docs/
│  ├─ README.md
│  ├─ progress.md
│  ├─ requirements/ (이전 버전: archive/)
│  ├─ database/ (이전 버전: archive/, ERD: erd/)
│  └─ screens/
├─ pom.xml
└─ src/
   ├─ main/
   │  ├─ java/com/travel/travel_recommendation/
   │  │  ├─ controller/
   │  │  ├─ service/
   │  │  ├─ repository/
   │  │  ├─ entity/
   │  │  ├─ dto/
   │  │  └─ config/
   │  └─ resources/
   │     ├─ templates/
   │     ├─ static/
   │     └─ application.properties
   └─ test/
```

기본 패키지는 `com.travel.travel_recommendation`이다. HomeController와 SignupController, SignupForm, UserService, UserRepository, User 및 권한·상태 enum, SecurityConfig를 구현했다. 회원가입 HTML·CSS·JS와 완료·403 안내 화면을 추가했다. 이미지 폴더는 아직 비어 있다.

`application.properties`는 두 SQL Server 프로필이 모두 없을 때 DataSource/JPA 자동 구성을 제외한다. SQL 로그인 프로필은 환경변수를, Windows 인증 프로필은 실행 계정을 사용한다. `ddl-auto=none`, `spring.sql.init.mode=never`로 자동 스키마 변경과 초기화를 끈 상태다. 현재 PC의 SQLEXPRESS 연결과 회원 테이블 검증을 완료했다.


한 PC에서 commit과 push를 마친 뒤 다른 PC에서 pull한다. 두 PC에서 같은 파일을 동시에 수정하는 상황을 피한다. 충돌 또는 분기 불일치가 발생하면 변경 내용을 확인해 해결하며 강제 push로 덮어쓰지 않는다.

노트북에 저장소가 아직 없다면 GitHub 저장소 주소를 확인해 최초 한 번 clone한다. Java, DB 접속정보, API Key 등 PC별 실행 환경은 별도로 설정한다. Git으로 공유할 진행 정보와 결정 사항은 이 문서에 남긴다.

- 최초 실제 GPT 응답은 서버 조건 검증에서 거부됐다. 원본 응답은 로그에 보관하지 않아 실패 필드를 사후 확정하지 않았다. 이후 출력 선택지를 활성 ID enum으로 제한하고 프롬프트 선택지를 표시명·선택값만 포함하도록 정리했다. 재호출에서 강릉·3일·2명·총예산 60만 원·숙박 필요·날짜 미정 검증을 통과했다. 실제 API 호출은 총 2건이며 마지막 호출에 사용량 제한 오류는 없었다.
- 개발 중 미정 기간 처리의 Integer 자동 언박싱 오류, 테스트 재시도 mock 재설정 오류와 JSON 스키마 복사의 명시적 타입 변환 누락을 수정했다. 실패 상태를 성공으로 기록하지 않고 재검증했다.
- 자동 테스트는 분석→보완→확정·선택 입력의 API 미호출·잘못된 AI 값·수정값·CSRF·세션 분리·중복과 오래된 응답·API 요청 형식·타임아웃·오류 안내 및 기존 회원·키워드 기능을 검사한다. 실제 유료 호출은 RUN_OPENAI_TESTS로 별도 선택한다.

- 실제 브라우저에서 DB 키워드 입력 → 보완 → 강릉·3일·2명·60만 원·숙박 필요로 수정 → 확정 화면을 확인하고 데스크탑 배치를 점검했다. 확인용 서버를 종료했다. 실제 브라우저에서의 유료 문장 분석 전체 흐름·모바일 기기·부하 시험은 미수행이며, 자연어 흐름은 MockMvc와 별도 실제 API 테스트로 검증했다. 추천 요청·AI 작업 DB 저장, 실제 장소 조회·여행 일정 생성은 구현하지 않았다.
