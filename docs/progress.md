## 5. 현재 기본 패키지 구조

```text
travel_recommendation/
├─ AGENTS.md
├─ docs/
│  └─ progress.md
├─ pom.xml
└─ src/
   ├─ main/
   │  ├─ java/com/travel/travel_recommendation/
   │  │  ├─ controller/
   │  │  ├─ service/
   │  │  ├─ repository/
   │  │  ├─ entity/
   │  │  ├─ dto/
   │  │  └─ config/
   │  └─ resources/
   │     ├─ templates/
   │     ├─ static/
   │     └─ application.properties
   └─ test/
```

기본 패키지는 `com.travel.travel_recommendation`이다. 애플리케이션 진입점과 `controller/HomeController.java`가 있으며 service/repository/entity/dto/config는 `package-info.java`로 구조만 마련되어 있다. 실제 Entity와 Repository 인터페이스는 없다. `static/css`, `static/js`, `static/images`는 `.gitkeep`으로 보존되어 있다.

`application.properties`는 `sqlserver` 프로필이 없을 때 DataSource/JPA 자동 구성을 제외한다. `application-sqlserver.properties`는 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` 환경변수를 참조한다. `ddl-auto=none`, `spring.sql.init.mode=never`로 자동 스키마 변경과 SQL 초기화를 비활성화했다. 실제 접속 정보와 연결 성공은 확인하지 않았다.

## 10. PC 간 Git 작업 방법

### 작업 시작

프로젝트 폴더에서 현재 브랜치와 미커밋 변경을 먼저 확인한다.

```powershell
cd C:\changp2\travel_recommendation
git status
git branch --show-current
```

미커밋 변경을 정리한 뒤 최신 코드를 받는다.

```powershell
git pull --ff-only
```

### 작업 완료

변경 내용과 비밀정보 포함 여부를 확인한다.

```powershell
git status
git diff
```

필요한 변경 파일만 추가한다. 아래는 두 문서만 반영하는 예이며, 코드 변경은 해당 파일 경로를 별도로 추가한다.

```powershell
git add AGENTS.md docs/progress.md
git diff --cached
git commit -m "Add project guidelines and progress documentation"
git push
```

한 PC에서 commit과 push를 마친 뒤 다른 PC에서 pull한다. 두 PC에서 같은 파일을 동시에 수정하는 상황을 피한다. 충돌 또는 분기 불일치가 발생하면 변경 내용을 확인해 해결하며 강제 push로 덮어쓰지 않는다.

노트북에 저장소가 아직 없다면 GitHub 저장소 주소를 확인해 최초 한 번 clone한다. Java, DB 접속정보, API Key 등 PC별 실행 환경은 별도로 설정한다. Git으로 공유할 진행 정보와 결정 사항은 이 문서에 남긴다.
