## 1. 장소 후보·중심 장소

### 1-2. 중심 장소가 GPT가 아는 이름에 의존함
- 중심 장소는 GPT가 추천 이유와 함께 적은 장소 이름과, 후보 한 곳에만 맞는 여행지 소개 단어로 고른다(`CenterPlaces.pick`). GPT가 적은 곳이 후보에 없으면 쓰지 못하고(예전 예: 안동 봉정사, 2026-09-24부터 사찰 검색으로 후보에 들어옴), 소개 단어가 여러 곳에 맞으면(예: "마을"·"서원") 건너뛴다.
- 검토 방향(2단계, DB 변경): 카카오 "○○ 명소" 검색 순위를 `places`에 저장해 대표성 판단에 쓴다. SQL 015·`Place`·`KakaoPlace`·`PlaceCandidate`·정렬·DB 정의서를 함께 바꿔야 하며, 다른 PC도 SQL 적용이 필요하다.

### 1-4. 예전 카카오 검색 결과가 24시간 동안 남음
- 관광지 검색 방식을 바꾸기 전(2026-09-23)에 저장된 카카오 장소는 24시간 캐시가 지나거나 '카카오에서 장소 더 찾아보기'로 다시 조회해야 새 결과로 바뀐다. 캐시가 지나면 저절로 해결된다. 2026-09-24에 추가한 사찰·성당 후보도 같은 방식으로, 재조회 전까지는 보이지 않는다.

## 2. AI 응답 품질

### 2-1. 추천 이유 길이·문장 품질을 보장하지 못함
- 추천 이유를 1~2문장·120자 안팎으로 지시했지만 GPT가 항상 지키지는 않는다(안동 약 160자, 스키마 상한 300자). 띄어쓰기 오류("함께해변을" 등)도 GPT 문장이라 서버가 고치지 않는다.
- 검토 방향: 화면에서 일정 길이를 넘으면 접어서 보여 주는 방법, 또는 서버에서 길이를 넘으면 한 번 다시 요청하는 방법.

### 2-2. 비슷한 곳 판단은 GPT가 함
- 문장 수정에서 후보에 없는 장소를 요청하면 비슷한 곳으로 바꾸는데, 어떤 곳이 비슷한지는 GPT가 고른다. "처럼·같은" 표현의 구분은 서버 규칙으로 보완했지만, 고른 장소가 사용자 기대와 다를 수 있다.

### 2-3. 되물은 기록이 세션에만 있음
- 콕 집은 장소를 한 번 되물었다는 기록은 세션에 둔다. 세션이 끝나면(30분 무동작·브라우저 종료) 같은 장소를 다시 되묻는다.

## 3. 비회원·세션

### 3-1. 공용 PC에서 비회원 추천이 다른 사람 이력으로 옮겨질 수 있음
- 로그인할 때 같은 세션의 비회원 추천·초안을 회원 이력으로 옮긴다. 공용 PC에서 창을 닫지 않은 채 다른 사람이 로그인하면 앞사람의 입력 문장이 포함된 추천이 옮겨진다.
- 검토 방향: 옮기기 전 확인을 받거나, 일정 시간 이상 지난 비회원 작업은 옮기지 않는 규칙을 검토한다.
