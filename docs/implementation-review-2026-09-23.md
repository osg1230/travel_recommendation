### 1. 저장 일정 수정이 임시 초안에 의존함 — 우선 보완 권장

> 해결(2026-09-23): 원래 초안이 없으면 저장 상세의 '수정 준비하기'가 저장한 조건·항목과 지금 확인된 장소 후보(카카오 재조회 포함)로 수정용 초안을 다시 만든다(`SavedItineraryEditService`). 저장 일정은 새 초안에 연결되며, 이후 소유권·버전·이어진 수정안 검사는 그대로 사용한다. 필수 방문 장소 설정은 저장 스냅샷에 없어 이어지지 않는다.

- `SavedItineraryService.editable()`은 저장 스냅샷의 jobId로 `RecommendationJobService.owned()`를 호출한다. 이 접근 검사는 만료된 작업을 거부한다.
- 추천 작업의 기본 보관 기간은 24시간이며, `AiJob.itinerary()`는 부모의 만료 시각을 그대로 이어받는다. 실제 기간은 설정값에 따라 달라진다.
- `RecommendationHistoryService.delete()`는 저장 일정은 남기지만 연결된 작업을 지운다. 이 경우에도 관광지·시간 수정 진입이 사라진다. 이름 수정·조회·삭제는 별개로 가능하다.
- 화면도 원본 초안 만료 시 여행 조건부터 새로 만들라고 안내한다. 따라서 저장 다음 날에도 이어서 수정한다는 일반적인 사용 흐름에 제한이 있다.
- 권장: 저장된 조건과 항목을 기준으로 새 수정 작업을 만들도록 하고, 필요한 외부 장소 정보는 다시 조회한다. 만료 기간을 늘리는 것만으로 해결하지 않는다. 소유권·버전 충돌 검사는 유지한다.
- 후속 검증: 초안 만료 후 수정, 추천 이력 삭제 후 수정, 타인 접근 거부, 두 화면에서 수정안 적용 충돌.

### 2. 초안에서 확인한 정보가 저장 일정으로 충분히 이어지지 않음

- 권장: 우선 저장 상세에 가격의 출처·조회 시각·확인 수준과 조건별 주의사항을 이어서 보여 준다. 오래된 참고값임을 표시하고 현재 가격처럼 취급하지 않는다. 기존 JSON 스냅샷을 활용할 수 있는지 검토하고 변경 시 스냅샷 정의도 맞춘다.
- 후속 검증: 가격 조회 후 저장, 새로고침·재로그인 후 표시, 수정안 적용 후 다른 장소의 가격이 남지 않는지.

### 3. 일정 수정의 지원 범위가 좁음

- `OpenAiRevisionClient`는 관광지 교체·시작/종료 시각·체류시간 변경만 지원한다. 식사·숙소·날짜·기간 변경과 새 장소 추가는 UNSUPPORTED로 안내한다.
- 이는 숨겨진 미구현이 아니라 명시된 제한이다. 발표에서도 “일정 전체 자유 수정”으로 설명하면 안 된다.
- 권장: 먼저 수정 화면에 지원 범위를 명확히 표시한다. 기능 확장은 사용자가 꼭 필요로 하는 항목 하나부터 범위를 정하고 요구사항과 함께 진행한다.
