# 프로젝트 실행 및 테스트 안내

기준일: 2026-09-19 · Windows / VS Code / PowerShell 기준

## 1. 현재 테스트할 수 있는 기능

현재 구현은 **회원가입·로그인·내 정보 수정 → 여행 조건 입력·보완·확정 → 여행지 후보 조회 → GPT 추천 순위·이유 확인**까지입니다. 후보 지역은 강릉·부산·경주입니다.

개별 관광지·숙소·음식점 추천, 시간대별 상세 일정 생성·저장·수정·삭제, 즐겨찾기와 관리자 회원 관리 기능은 아직 테스트 대상이 아닙니다. 요구분석서의 구현 예정 기능과 구분해 주세요.

| 목적 | 실행 방법 | 준비물 |
| --- | --- | --- |
| 먼저 화면과 조건 입력 확인 | 3절: DB 없이 실행 | Java 21 |
| 회원 기능·여행지 후보 조회 | 4절: Windows 인증 DB 실행 | Java 21, SQL Server 2019, SQL 001~006 적용 |
| 문장 분석·GPT 추천 확인 | 서버 실행 전 5절 API 키 설정 | API 키 추가 |

## 2. 터미널과 Java 준비

VS Code에서 프로젝트 폴더를 열고 **터미널 → 새 터미널**에서 PowerShell을 선택합니다. 명령은 같은 터미널에서 순서대로 실행합니다.

```powershell
Set-Location 'C:\changp2\travel_recommendation'
java -version
.\mvnw.cmd -version
```

두 명령 모두 Java 21을 표시하면 그대로 진행합니다. Maven은 프로젝트 Wrapper를 사용하므로 별도 설치하지 않아도 됩니다. 최초 빌드에는 의존성 다운로드를 위한 인터넷 연결이 필요합니다.

다른 Java 버전이 표시되면 현재 터미널에서 JDK 경로를 설정합니다. 아래는 이번 PC에서 확인한 경로이며 다른 PC에서는 실제 설치 폴더로 바꿉니다. `JAVA_HOME`에는 `bin`이 아닌 JDK 폴더를 지정합니다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.12.8-hotspot'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\mvnw.cmd -version
```

기존 `. .\scripts\use-java21.ps1`은 사용자 `.jdks`의 Java 21을 찾는 스크립트입니다. 다른 위치는 `-JdkPath`로 지정해야 합니다. 이번 PC에는 해당 폴더가 없으며 스크립트 실행 정책도 제한되어 있으므로, 위 직접 설정 방식을 사용하면 됩니다.

터미널을 새로 열면 터미널에서 지정한 환경변수도 다시 설정합니다. 이전 서버가 실행 중이면 해당 터미널에서 **Ctrl+C**로 종료하고 새로 실행합니다.

## 3. 가장 먼저: DB 없이 화면 실행

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=default"
```

터미널에 `Started TravelRecommendationApplication`이 표시되면 브라우저에서 **http://localhost:8080/** 을 엽니다. 서버 실행 중 터미널이 명령 입력 대기 상태로 돌아오지 않는 것이 정상입니다.

1. 홈에서 **여행 조건 입력하기**를 누릅니다.
2. **조건 고르기**에서 여행 일수 3일, 여행 취향 바다 등 원하는 조건을 선택합니다.
3. **입력 내용 확인하기**를 누르고 선택한 값이 맞는지 확인합니다.
4. **조건 보완·확정하기**로 이동해 내용을 보완하고 확정합니다. 수정 화면으로 돌아갔을 때 이전 입력이 유지되는지도 확인합니다.

이 모드는 예시 선택지를 사용합니다. 실제 회원 기능과 여행지 후보 조회는 4절로 실행해야 합니다. API 키가 있으면 DB 없이도 문장 분석은 가능합니다.

## 4. 회원 기능·여행지 후보까지 실행

### DB 준비 확인

기존 진행 기록에는 이 PC의 `SQLEXPRESS`, TCP 1433, `travel_recommendation` DB에 SQL 001~006을 적용한 것으로 기록되어 있습니다. 이번 문서 작업에서 현재 DB 접속이나 적용 상태를 다시 확인한 것은 아닙니다. 이미 준비한 PC라면 아래 실행 명령부터 진행하세요.

새 PC에서는 SQL Server 2019 서비스와 접속 가능한 `travel_recommendation` DB를 준비하고, SSMS에서 해당 DB를 선택해 다음 SQL을 순서대로 적용합니다. **앞 파일의 성공을 확인한 뒤 다음 파일로 진행**합니다. Git pull만으로 DB가 준비되지는 않습니다.

| 순서 | 파일 (`docs/database/sql/`) | 역할 |
| --- | --- | --- |
| 1 | `001_create_users.sql` | 회원 테이블 |
| 2 | `002_create_keywords.sql` | 조건 카테고리·키워드 테이블 |
| 3 | `003_seed_keywords.sql` | 초기 선택지 |
| 4 | `004_create_recommendation_jobs.sql` | 추천 요청·작업·장소 테이블 |
| 5 | `005_seed_destinations.sql` | 강릉·부산·경주 데이터 |
| 6 | `006_create_recommendation_results.sql` | 추천 결과 테이블·작업 상태 반영 |

기존 테이블 때문에 생성 SQL이 중단되면 삭제·재생성하지 말고 적용 상태를 확인해 빠진 단계만 진행합니다. 앱은 테이블을 자동 생성하지 않습니다. 설계는 [DB 정의서](database/DB_테이블_정의서.md), 상세 준비는 [후보 조회 문서](ai/여행지_후보_조회.md)를 참고합니다.

### Windows 인증으로 실행

Java 21을 확인한 같은 터미널에서 실행합니다. AI도 테스트하려면 **5절의 API 키 설정을 먼저** 합니다.

```powershell
# Windows 인증 DLL 준비: 최초 1회 (이미 있으면 생략 가능)
.\mvnw.cmd dependency:get "-Dartifact=com.microsoft.sqlserver:mssql-jdbc_auth:13.4.0.x64:dll" "-Dtransitive=false"

# 일반 자동 테스트와 Jar 빌드: DB/유료 API 테스트는 실행하지 않음
$env:RUN_SQLSERVER_TESTS = 'false'
$env:RUN_OPENAI_TESTS = 'false'
$env:RUN_OPENAI_RECOMMENDATION_TESTS = 'false'
.\mvnw.cmd clean verify
```

**`BUILD SUCCESS`를 확인한 뒤에만** 다음을 실행합니다. 실패했다면 이전 Jar로 진행하지 말고 빌드 오류부터 확인합니다.

```powershell
$jdbcAuthPath = Join-Path $env:USERPROFILE '.m2\repository\com\microsoft\sqlserver\mssql-jdbc_auth\13.4.0.x64'
java "-Djava.library.path=$jdbcAuthPath" -jar target/travel_recommendation-0.0.1.jar --spring.profiles.active=sqlserver-windows
```

`Started TravelRecommendationApplication` 확인 후 **http://localhost:8080/** 에 접속합니다. Windows 인증은 Java를 실행한 Windows 계정의 DB 권한을 사용합니다. Maven 로컬 저장소 위치를 변경했다면 `$jdbcAuthPath`도 실제 DLL 폴더로 바꿉니다.

기본 DB 주소는 `localhost:1433`, DB 이름은 `travel_recommendation`입니다. 다른 환경이라면 서버 실행 전에 실제 값으로 설정합니다.

```powershell
# 로컬 개발용 예시: 포트와 DB 이름을 실제 값으로 수정
$env:DB_URL = 'jdbc:sqlserver://localhost:1433;databaseName=travel_recommendation;integratedSecurity=true;authenticationScheme=NativeAuthentication;encrypt=true;trustServerCertificate=true'
```

SQL 아이디·비밀번호로 접속하는 PC는 [README의 SQL 로그인 안내](../README.md#sql-로그인-또는-다른-서버)를 사용합니다. `sqlserver`와 `sqlserver-windows`를 동시에 활성화하지 않습니다.

## 5. 문장 분석·GPT 추천용 API 키

서버 실행 환경의 `OPENAI_API_KEY`를 사용하며, 없으면 `Portfolio_java_API`를 사용합니다. 이미 Windows 환경변수에 설정했다면 새 VS Code 터미널에서 서버를 실행합니다. 키의 존재 여부만 확인하려면 다음 명령을 사용합니다.

```powershell
[bool]($env:OPENAI_API_KEY -or $env:Portfolio_java_API)
```

`False`면 서버 실행 전에 다음 명령으로 키를 입력할 수 있습니다. 키 문자열을 명령에 직접 적지 않고 암호 입력란에 넣습니다.

```powershell
$apiCredential = Get-Credential -UserName 'OpenAI' -Message 'Password 칸에 API 키를 입력하세요'
if ($null -ne $apiCredential) {
    $env:OPENAI_API_KEY = $apiCredential.GetNetworkCredential().Password
    Remove-Variable apiCredential
}
```

키를 문서·소스 코드에 저장하지 마세요. `.env` 파일은 자동으로 읽지 않습니다. 실행 중인 서버는 환경변수 변경 후 재시작해야 적용됩니다. 현재 코드의 기본 모델은 `gpt-4.1-mini`이며 `OPENAI_MODEL`로 바꿀 수 있습니다.

**문장 분석하기**와 **GPT 추천 받기**는 실제 API를 호출하므로 사용료가 발생합니다. **조건 고르기 → 여행지 후보 찾기**까지는 API 키 없이 테스트할 수 있습니다.

## 6. 직접 테스트할 순서

4절의 DB 모드로 실행하고 테스트용 계정을 사용합니다. 화면에서 가입하거나 정보를 수정하면 실제 DB에 반영됩니다.

| 순서 | 해 볼 동작 | 정상 결과 |
| --- | --- | --- |
| 1 | `/signup`에서 새 아이디·닉네임으로 가입 | 가입 완료 화면 |
| 2 | `/login`에서 틀린 비밀번호 입력 후 올바른 비밀번호로 재시도 | 실패 안내 후 정상 로그인 |
| 3 | `/account`에서 현재 비밀번호와 새 닉네임 입력 | 닉네임 변경, 로그인 유지 |
| 4 | 로그아웃 후 `/account` 접속 | 로그인 화면으로 이동 |
| 5 | `/travel/conditions` → 조건 고르기 → 3일·바다 등 선택 → 입력 내용 확인 | 입력값 표시 |
| 6 | 조건 보완·확정하기 → 지역 미정으로 확정 → 여행지 후보 찾기 | 잠시 후 강릉·부산·경주와 공식 출처 표시 |
| 7 | 조건을 수정해 지역을 강릉으로 확정하고 후보 조회 | 강릉만 표시 |
| 8 | 지역을 제주로 바꿔 후보 조회 | 지원 지역·조건 수정 안내 |
| 9 | 비회원 상태에서 만든 결과 주소를 다른 시크릿 창에서 열기 | 다른 세션에서 접근 불가(404) |
| 10 | API 키 설정 후 문장으로 적기 → 확인 → 문장 분석하기 | 분석 결과 표시, 보완·확정 가능 |
| 11 | 지원 지역 조건 확정 → 후보 찾기 → GPT 추천 받기 | 처리 상태 후 추천 순위·이유·출처 표시 |

아이디는 영문·숫자·밑줄 4~50자, 닉네임은 2~50자입니다. 비밀번호는 영문과 숫자를 포함한 8~64자이며 공백은 사용할 수 없습니다. 기존 계정과 겹치면 다른 아이디·닉네임으로 테스트합니다.

문장 분석 예시:

> 친구와 2명이서 2박 3일 동안 바다를 보며 쉬고 싶어. 총예산은 60만 원이고 대중교통을 이용할 거야. 지역은 아직 정하지 않았어.

분석 결과가 원문과 맞는지 확인하고 틀리거나 빠진 값은 수정한 뒤 확정합니다. 현재 후보는 저장된 지역 정보이며 실시간 관광 API 조회가 아닙니다. 추천 이유가 표시되어도 실제 비용·영업시간·이동시간을 검증한 상세 일정은 아닙니다.

## 7. 종료·재실행과 오류 해결

- **종료:** 서버 터미널에서 `Ctrl+C`. 배치 작업 종료 질문이 나오면 `Y`를 입력합니다.
- **재실행:** 2절의 Java 확인 후 사용한 실행 명령을 다시 실행합니다. 코드를 수정했다면 Jar 실행 전 다시 빌드합니다.
- **8080 포트 사용 중:** 이전 프로젝트 서버를 종료합니다. 다른 프로그램을 유지해야 하면 Jar 실행 명령 끝에 `--server.port=8081`을 붙이고 `http://localhost:8081/`을 엽니다.
- **Java/JAVA_HOME 오류:** `java -version`과 `.\mvnw.cmd -version`이 모두 Java 21인지 확인합니다.
- **`Unable to access jarfile`:** 프로젝트 루트인지, `clean verify`가 성공했는지 확인합니다.
- **DB 연결 거부·시간 초과:** SQL Server 서비스, TCP/IP 사용 여부, 실제 포트와 `DB_URL`을 확인합니다. `Test-NetConnection localhost -Port 1433`은 포트만 확인하며 DB 로그인 성공을 뜻하지 않습니다.
- **`integrated authentication`/DLL 오류:** DLL 다운로드 성공 여부, `java.library.path`, Java·DLL의 64비트 및 JDBC 버전 일치를 확인합니다.
- **테이블 없음(`Invalid object name`):** DB 이름과 SQL 001~006 적용 상태를 확인합니다. `ddl-auto=create`로 해결하지 않습니다.
- **회원 화면에서 DB 모드 안내:** DB 없이 실행한 상태입니다. 4절 프로필로 재실행합니다.
- **GPT 인증·사용량·통신 오류:** 실행 터미널의 키 설정, API 사용 가능 상태와 네트워크를 확인하고 화면 안내에 따라 재시도합니다.
- **세션 만료·조건 없음:** 입력 화면으로 돌아가 다시 입력·확정합니다. 기본 세션 만료 시간은 30분입니다.

문제를 전달할 때는 **실행한 명령, 오류가 난 화면과 단계, 터미널 오류 메시지**를 알려 주세요. API 키와 비밀번호는 제외합니다.

## 8. 이번 안내의 확인 범위

- `pom.xml`, 실행 프로필, Java 선택 스크립트, Controller 경로, 기존 실행·설계 문서와 대조했습니다.
- 이번 PC에서 Maven Wrapper 3.9.16 / Java 21.0.12 사용과 Windows 인증 DLL 파일 존재를 확인했습니다.
- 이번 작업은 문서 추가입니다. 앱 실행, Maven 전체 테스트, 현재 DB 접속·스키마 확인과 유료 API 호출은 새로 수행하지 않았습니다. 위 표는 사용자가 직접 확인할 테스트 항목이며 통과 기록이 아닙니다.
